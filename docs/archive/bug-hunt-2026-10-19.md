## 3. Findings

### N3. Solve reuses a root's rounded display value (family 1)

**Seen (verified; engine side probed, app side read).**

| Step | Input | Shown | Right |
|---|---|---|---|
| 1 | solve `x²=2` for x, guess 1 | `≈ 1.41421356237` | ≈ 1.41421356237 |
| 2 | solve `y=x²` for y, with x known | `≈ 1.99999999999`, 29 digits confirmed | 2 |
| 2′ | solve `y=(x−1.41421)·10⁶` for y, with x known | `≈ 3.56237`, 29 digits confirmed | 3.56237309505 |

When the engine is given x's confirmed digits instead (`result.full`, 1.4142135623730950488016887242), the same requests give 2 and 3.56237309505.

**Cause.**
- The Solve app keeps each unknown's value as the text of its 12-digit display. `setFromResult` stores `display` ([app.svelte.ts:321](../../app/src/apps/solve/app.svelte.ts#L321)).
- `solve()` sends `this.value(u)` as both the known value and the guess ([app.svelte.ts:262](../../app/src/apps/solve/app.svelte.ts#L262), [:92](../../app/src/apps/solve/app.svelte.ts#L92)).
- The confirmed digits are kept in `copies[name]` ([app.svelte.ts:72](../../app/src/apps/solve/app.svelte.ts#L72)), but only Copy reads them.
- The engine takes the known as an exact decimal (`knownSubst`, [solve.ts:101](../../app/src/engine/solve.ts#L101)). So both polishes solve the same rounded problem and agree on 29 digits.

**Same pattern as** §2.3 #8 (R2): there, a chip carried the rounded digits, and `1/3`, tap, `×3` gave 0.999999999999. The chip carrier was fixed; the Solve app's knowns never got that fix.

**Also (inferred from the code):**
- After the digits setting goes from 12 to 30, the table still holds the 12-digit text.
- A ⚠ root keeps its `warned` flag but not its confirmed digits, so a later solve that uses it as a known does not inherit them.

**Fix.**
- Keep the value and the display apart. The value an unknown carries into the engine is every confirmed digit (`result.full`, which is what `copies` holds now), together with its facts (confirmed digits and warn).
- `KnownValue` gets those facts, and `solve.ts` caps the result's confirmed digits by them, the way a chip's facts cap a Home result (decisions M4-7).
- The table keeps showing the display. A value the user typed stays exact.

**Test first.** An app test, or a sequence through `solveRequest`:
- `x²=2`, then `y=x²` with x known: y is 2, not 1.99999999999.
- `y=(x−1.41421)·10⁶`: 3.56237309505.

**Which generator would have found it.** G62's carrier × fact sequences, with "a Solve root used as a known" as a carrier.

### N4. Home lends a stored name's facts to a bound variable of the same name (families 8 and 1)

**Seen (verified).**

| Stored x | Input | Shown | Right |
|---|---|---|---|
| none | `sum(x^2,x,1,10)` | `= 385` | = 385 |
| `x:=sin(1)` (≈, 38 digits) | `sum(x^2,x,1,10)` | `≈ 385` | = 385 |
| `x:=normald_icdf(0.025)` (⚠, unaudited) | `sum(x^2,x,1,10)` | `⚠ 385`, why "inherited: x" | = 385 |
| same | `int(x^2,x,0,1)` | `⚠ 0.333333333333`, "inherited: x" | ≈ 0.333333333333 |
| same | CAS `evalf(int(x^2,x,0,1))` | ⚠; the why lists `int` and `x` | ⚠ (`int` is unaudited); the why lists `int` only |

The CAS results without a float (`sum(x^2,x,1,10)` = 385, `int(x^2,x,0,1)` = 1/3) stay unmarked, as they should: G51's `readFacts` masks bound names.

**Cause.**
- `inherited()` collects the names it lends facts from with `namesIn(input)` ([host.ts:434](../../app/src/engine/host.ts#L434)), without masking bound names.
- CAS's `usesOf` ([host.ts:656](../../app/src/engine/host.ts#L656)) and `readFacts` ([host.ts:525](../../app/src/engine/host.ts#L525)) use `maskBound` ([host.ts:133](../../app/src/engine/host.ts#L133), the QUOTING table).
- CAS's float path calls `inherited()` too ([host.ts:772](../../app/src/engine/host.ts#L772)), which gives the extra "x" in the last row.
- Inferred: the perturbation check also moves x and runs the sum once more for nothing, one Giac call per such input (family 13).

**A trap for the fix (verified).** Home and CAS differ on `diff`:
- In CAS, `diff(x^3,x)` with x:=3 stays `3*x^2`.
- Home goes on to evaluate the derivative's value, so Home `diff(x^3,x)` reads the stored x: 11.5243764621 with x = normald_icdf(0.025). There, x's facts are rightly lent.
- `solve`, `limit`, definite `int`, `sum`, `seq`, `product` and `fsolve` give the same result with x stored or free.
- So Home needs `maskBound` without the `diff` row, not `maskBound` as it is.

**Fix.** In `inherited()`, take the names from the masked text: Home's variant leaves `diff` out of QUOTING. Take `moved` from the same list.

**Test first.** Golden sequence cases in G34's form:
- `x:=normald_icdf(0.025)`, then `sum(x^2,x,1,10)` is `= 385`.
- `int(x^2,x,0,1)` is `≈ 0.333333333333` with no ⚠.
- Home `diff(x^3,x)` keeps ⚠ with "inherited: x".

**Which generator would have found it.** G62 with a bound-variable column; G55's corpus run through Home and CAS.

### N5. Copy session writes `⚠ 39` on ordinary results (families 6 and 8)

**Seen (verified).**

| Input | Screen | Session line written by Copy session |
|---|---|---|
| `sqrt(2)` | `≈ 1.41421356237` | `sqrt(2) ⚠ 39 1.41421356237309504880168872420969807857` |
| `pi` | `≈ 3.14159265359` | `pi ⚠ 39 3.1415926535897932384626433832795028842` |
| `ln(2)` | `≈ 0.69314718056` | `ln(2) ⚠ 38 0.69314718055994530941723212145817656808` |
| `1/3` | `≈ 0.333333333333` | `1/3 ≈ 0.3333…` (right) |

**Cause.**
- `copyMark` returns `⚠ n` when `reliableDigits` < 40 and a part of the value has more digits than that ([text.ts:119](../../app/src/clipboard/text.ts#L119)).
- A value from the agreement check keeps P+2 = 42 digits (`exactFactsOf` reads with `P + 2`, [numeric.ts:619](../../app/src/engine/numeric.ts#L619)).
- That value is confirmed to 38 or 39 digits: `confirmedDigits`' interval spans one unit in the last place of the 40-digit print. So every irrational result meets the condition.
- The copy itself (`copyFull`) already cuts to the confirmed digits, so the `⚠ n` never describes the text it is written next to.
- The unit test uses a hand-made 19-digit value with 19 confirmed digits ([text.test.ts:101](../../app/src/clipboard/text.test.ts#L101)), so it never meets engine data.
- `copyMark`'s only caller is `sessionText` (Copy session, [actions.svelte.ts:134](../../app/src/clipboard/actions.svelte.ts#L134)).

**Fix.** One rule instead of two: the session line carries the mark the screen shows, which is `markOf` with the item's display settings. √2 then gets `≈`, and the existing `⚠ 5` cases (a value confirmed to 5 digits) keep `⚠ 5`, as on screen.

**Test first.** Session text of engine-made items (√2, π, ln 2) gets `≈`. The existing cases are unchanged.

**Which generator would have found it.** A test that feeds real engine results to the copy code: family 14's "the test path differs from the app path".

### N6. The Function app's Area refuses integrals that converge (families 8 and 5)

**Seen (verified).**

| Integrand, bounds | Function app Area | Home `int(…)` | Right |
|---|---|---|---|
| `ln(x)`, [0, 1] | refused: "the integral does not converge (undef)" | −1 | −1 |
| `x·ln(x)`, [0, 2] | refused, same text | 0.38629436112 | 2·ln 2 − 1 = 0.386294361120 |
| `(1−cos x)/x²`, [−1, 1] | refused, same text | 0.972770752471 | 0.972770752471 |
| `sin(x)/x`, [0, 1] | 0.946083070367 | 0.946083070367 | same |
| `1/x`, [−1, 1] | refused | refused (`integralDiverges`) | diverges |

**Cause.**
- [analysis.ts:160–161](../../app/src/engine/analysis.ts#L160): any Romberg answer that is neither a number nor a list is reported as "does not converge".
- Romberg returns `undef` whenever the integrand is undefined at a point it samples: ln 0, 0·ln 0, or 0/0 at the midpoint of a symmetric interval. That says nothing about convergence.
- The exact `int()` is tried only after Romberg's list answer, which means "did not converge" ([analysis.ts:169](../../app/src/engine/analysis.ts#L169)).

**Reach.** The Area bounds come from the trace, which snaps to a decimal grid ([app.svelte.ts:415](../../app/src/apps/function/app.svelte.ts#L415), [:488](../../app/src/apps/function/app.svelte.ts#L488)). So 0 and ±1 are ordinary cursor positions on the default window.

**Fix.**
- On `undef`, try the exact `int()` within `EXACT_INT_S`, as for the list answer.
- Apply `converge.ts`'s refusals as Home does: `1/x` across 0 stays refused, with Home's reason.
- Then fall back to Gauss quadrature with ⚠.
- Refuse only where Home refuses: one rule for Home and the Function app.

**Test first.** In the analysis tests:
- ln(x) on [0, 1] gives −1.
- x·ln(x) on [0, 2] gives 0.38629436112.
- (1−cos x)/x² on [−1, 1] gives 0.972770752471.
- 1/x on [−1, 1] is still refused.

**Which generator would have found it.** G63, one value in every view: Home's `int` and the Function app's Area run on the same corpus.

### N7. Giac's `round(x,n)` and `trunc(x,n)` work in a double, and `round` is audited (family 4)

**Seen (verified).**

| Input | Digits | Shown | Right |
|---|---|---|---|
| `round(sin(10^50),5)` | 12 | `≈ 0.59587` (39 digits confirmed) | −0.78967 |
| CAS `round(sin(10^50),5)` | 12 | `≈ 0.59587` | −0.78967 |
| `round(2/3,20)` | 30 | `≈ 0.6666666666666666667` | 0.66666666666666666667 |
| `round(pi,25)` | 30 | `≈ 3.14159265358979323846264` | 3.1415926535897932384626434 |
| `round(10^17+1/3,2)` | 30 | `≈ 100000000000000000` | 100000000000000000.33 |
| `trunc(sin(10^50)*10^12,0)` | 12 | `= 595872309788` | −789672493429 |
| `trunc(sin(10^50),5)` | 12 | `⚠ 0.59587` (flagged: trunc is unaudited) | −0.78967 |

Raw Giac gives the same answers whatever `Digits` is:
- `round(2/3,20)` prints `0.6666666666666666667` at Digits 14, 40 and 60.
- `round(10^17+1/3,2)` prints `1e+17`.
- `trunc(sin(10^50),5)` prints `0.59587` at Digits 12, 40 and 60 (sine of the double 1e50, which is not 10^50).

So Giac computes the two-argument forms in a double, or in about 19 digits for larger n. I did not read Giac's source for it.

**Cause on our side.**
- `round` is on `AUDITED_FUNCTIONS` ([numeric.ts:57](../../app/src/engine/numeric.ts#L57)), so the agreement check trusts two runs that return the same double.
- `trunc(x,0)` prints an integer, so the exact path reads it as an exact rational and shows `=`.

**Relation to G47 and G42f1.**
- G47's cases are `round(12.345,2)`, `round(π,3)`, `round(−0.125,2)` and `trunc(2.567,2)` ([home.yaml:183–190](../../tests/golden/home.yaml#L183)). All of them have short results and arguments whose double is exact enough.
- Their notes already say "round returns a Giac double, hence ≈". None of them meets a double that is wrong, or a result longer than 15 digits.
- G42f1 (n19 2.1) met the same function through `shortDigits`.

**Reach.**
- Today only as Giac text (the golden cases, a probe). `round` is in the parser's `NAMED_FUNCS` ([parse.ts:223](../../app/src/input/parse.ts#L223)), but no key, palette or tier-0 Find entry inserts it.
- Find lists `round` and `trunc` in tier 1, which R4a makes one tap away.
- Library bodies (R59) reach both.

**Fix.**
- Our own `pasround(x,n)` and `pastrunc(x,n)` in `ENGINE_DEFINITIONS`, built as `sigfig` is: exactly `round(x·10^n)/10^n`, keeping Giac's half-up tie rule (S12, G45), with x evaluated at n+30 significant digits when it is not rational.
- `CALL_NAME` renames the two-argument calls ([emit.ts:159](../../app/src/input/emit.ts#L159)). As stored definitions they are then decided twice (`notBuiltin`), and `decisionCuts` already knows round's half-integer cut.
- Until then, take two-argument `round` off the audited list.

**Test first.** The rows above as golden cases, with mpmath oracle values.

### N8. `trunc` and `Heaviside` are missing from the decision functions (family 3)

**Seen (verified).**

| Input | Shown | Right |
|---|---|---|
| `floor(sin(10^70)*10^12)` | `= -148099131372` | right (G38) |
| `sign(sin(10^70))` | `= -1` | right (G38) |
| `trunc(sin(10^70)*10^12)` | `= 387557674394` | −148099131371 |
| `Heaviside(sin(10^70))` | `= 1` | 0 |

**Cause.**
- `evalf(sin(10^70),30)` is −0.53871… (wrong; right: −0.14810…). At P = 40 digits (133 bits) the MPFR argument 10^70 is not exact, because 5^70 needs 163 bits.
- G38's second decision at P+20 and P+40 catches this, but only for the names on `DECISION_FUNCTIONS` ([numeric.ts:943](../../app/src/engine/numeric.ts#L943)) and in `decisionCuts` ([numeric.ts:1120](../../app/src/engine/numeric.ts#L1120)).
- 10^50 does fit in 133 bits (5^50 needs 117), which is why `trunc(sin(10^50)*10^12)` happens to be right. Tests should use 10^70.

**Reach.** `trunc` and `Heaviside` are tier 1 in Find (R4a); library bodies (R59) reach them too.

**Fix.**
- Add `trunc` (an integer cut, like `floor`) and `Heaviside` (a zero cut, like `sign`) to `DECISION_FUNCTIONS` and `decisionCuts`.
- Add `trunc` to `RATIONAL_FUNCTIONS` ([numeric.ts:967](../../app/src/engine/numeric.ts#L967)).
- Before R4a, take a census of the tier-1 functions that make a decision (family 3's hunt list): a probe on `sin(10^70)` per function finds each one.

**Test first.** The two wrong rows as golden cases.

### N9. A library body can change state twice per Enter, unlogged (families 9 and 3)

**Seen (verified).** This file passes `parseLibrary` and imports through `importLibrary`:

```
// pascaline library 1
// a counter
cnt:=0
// bumps the counter
bump(x):={ increment(cnt); return x; }
// drops beam
drop(x):={ DelVar(cnt); return x; }
```

Then each Home Enter changes cnt by 2, and writes no defs entry:

| Home input | cnt after it | defs |
|---|---|---|
| `bump(1)` | 2 | none |
| `bump(sin(1))` | 4 | none |
| `bump(floor(sqrt(2)))` | 6 | none |

**Cause, in three parts.**
1. **The library guard.** `STATE_WORDS` ([library.ts:22](../../app/src/engine/library.ts#L22)) lists `purge` but not `DelVar`, and neither `increment` nor `decrement`. `globalAssigned` ([library.ts:126](../../app/src/engine/library.ts#L126)) sees only the spelled-out forms (`:=`, `++`, `+=`), not the calls.
2. **Run-once detection.** Giac prints `increment(cnt)` back as `cnt++`, and `DelVar(b)` as `DelVar b` (verified). `definitionStores` ([numeric.ts:1012](../../app/src/engine/numeric.ts#L1012)) matches `:=`, `=>`, `sto`, `purge` and `assume`, but not `++`, `--`, `+=`, `-=` or `DelVar`. So `callsStateful` says the call may run twice, and Home runs it twice: the exact run, then G38's second decision.
3. **The defs log.** `isStateful` ([homeEval.ts:399](../../app/src/engine/homeEval.ts#L399)) misses the same forms, so nothing reaches the log, and after a relaunch cnt is back to its imported value.

A function whose printed body holds `b+=1` fools `definitionStores` in the same way (inferred; Giac keeps `b+=1` in the print, verified).

**Reach.** None today: the app does not call `importLibrary`. After R59, any library file. `increment`, `decrement` and `DelVar` are not in the Find index.

**Fix.**
- `definitionStores` and `isStateful` match `++`, `--`, `+=`, `-=`, `*=`, `/=`, and the calls `increment`, `decrement` and `DelVar` (also the printed form `DelVar name`).
- `STATE_WORDS` adds `DelVar`, `increment` and `decrement`, together with N2's `approx_mode`, `epsilon` and `complex_variables`.
- This belongs with G54, before R59.

**Test first.**
- A library test: the file above is refused.
- A host test: a stored function whose body increments a global runs once per Enter.

### N10. `purge` keeps the entries that were kept as typed (family 1, the defs replay)

**Seen (verified).** CAS `x:=y:=3` is logged as one entry of kind "other", `x:=y:=3`. Then `purge(x)` and `purge(y)` leave the log unchanged. Live, x and y are free; after a relaunch (the log replayed into a fresh engine) both are 3.

**Cause.**
- `applyDefChanges` keeps every "other" entry on a purge ([defs.ts:70](../../app/src/engine/defs.ts#L70)).
- `x:=y:=3` is "other" because its right side stores, so `defsAfter` takes neither name as the target.

**Reach.** Low. No key types `:=`: the store key types ▶, and the parser refuses a second ▶. A library also refuses a value that defines something. But any future way to make "other" entries meets this.

**Fix.** Either drop, on a purge, the "other" entries that set a purged name, or, with S13, read the names a line set from Giac's `VARS()` and record each one as a variable, so that "other" goes away.

## 7. How to rerun

Run from the worktree root (`.claude/worktrees/phase-1`) with Node 22; the engine is found as `tools/probes/engine.ts` finds it. Save this as `seq.ts` outside the repo. Each argument is `h:<Giac text>` for Home, `c:<Giac text>` for CAS, or `r:<text>` for a raw `giac.eval`. Set `ANGLE=deg` or `DIGITS=n` as needed.

```ts
const W = `${process.cwd()}/app/src`;
const { EngineHost } = await import(`${W}/engine/host.ts`);
const { loadNodeGiac } = await import(`${W}/engine/nodeGiac.ts`);
const { defaultHomeSettings } = await import(`${W}/engine/homeEval.ts`);
const { defaultCasSettings } = await import(`${W}/engine/types.ts`);
const { markOf } = await import(`${W}/engine/format.ts`);
const { giac } = await loadNodeGiac();
const host = new EngineHost(giac);
const digits = Number(process.env.DIGITS ?? 12);
const angle = process.env.ANGLE === "deg" ? "deg" : "rad";
const hs = { ...defaultHomeSettings, digits, angle, workDigits: Math.max(30, digits + 10) };
for (const arg of process.argv.slice(2)) {
  const [kind, ...rest] = arg.split(":");
  const input = rest.join(":");
  if (kind === "r") { console.log("raw", input, "=>", giac.eval(input)); continue; }
  if (kind === "c") {
    const { result: r } = host.cas(input, { ...defaultCasSettings, digits, angle });
    const m = r.numeric ? markOf(r.numeric, { format: "STD", digits }) : r.approximate ? (r.warn ? "⚠" : "≈") : "";
    console.log("CAS ", input, "=>", JSON.stringify(m), r.ok ? r.text : `ERR ${r.error}`, JSON.stringify(r.numeric?.why ?? r.why ?? {}));
    continue;
  }
  const { result: r, defs } = host.home(input, hs);
  console.log("HOME", input, "=>", JSON.stringify(markOf(r, { format: "STD", digits })), r.ok ? r.display : `ERR ${r.error}`,
    `rel=${r.reliableDigits}`, JSON.stringify(r.why ?? {}), defs.length ? JSON.stringify(defs) : "");
}
```
