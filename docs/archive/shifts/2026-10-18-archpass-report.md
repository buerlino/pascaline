### Pipeline findings, verified (2026-10-18)

No real pipeline run has happened yet (.tasks/counter = 0, no NNN-* run dirs), so this was never seen. Fix: one export line in pipeline.sh (and brief section 8 names QALC_OUT only).
- **P-B: combined package blocks cannot start.** The heading regex finds a block only for `### <agent>, … <ID> …`; the branch is read from the first `branch \`…\`` in the heading. Dry runs: R15c2/R15c3/R15c4 → "has no heading" (heading says R15c1–R15c4); R15c1, R12a/R12b/R12c, R38a/R38b → silent exit 1 with no message (the heading says "branches", the grep in `branch="$(grep … | sed)"` fails under `set -eo pipefail`). - **P-C: a `die` leaves no RESULT line and night.sh loops on it.** `die "host-cpu lock busy"` (after waiting 1800 s) and `die "phase-1 worktree … is not clean"` exit 2; night.sh treats rc≠75 as done, henri sees no RESULT line for the step and replies with the same command, up to --max-steps 40 henri calls. By day, parallel runs each wait up to 30 min for the host-cpu lock (e2e ≈ 5–7 min per run, golden on top), so the wait can run out.
- **P-D: two merges at once.** The merge step takes no lock; a second `git merge` fails on index.lock and its `merge --abort` runs while the first may still be in progress. Needs a lock around merge (and around the Opus pass's commit on phase-1).
