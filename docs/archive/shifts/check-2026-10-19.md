## Part 1: findings, by severity

### High: silent wrong numbers

1. **A Home value stored in one angle mode changes value in the other** (**verified** on `cb1c74c`; the same store form `name:=(exact text)` is in `origin/phase-1`, `host.ts:335` there, read, not run). `TH:=atan(3/4)` in DEG shows 36.8698976458 and stores the command `TH:=(atan(3/4))` with preview `36.8698976458`. In RAD, `TH` gives 0.643501108793 ≈ and `2*TH` 1.28700221759, while the preview Vars will show still says 36.87. The same goes for `S:=sin(1)` (DEG 0.0174524064373, then RAD 0.841470984808), and the other way round (`V:=sin(1)` in RAD, then DEG 0.0174524064373). Ans and a tapped `\res` chip carry the same exact text: `chipFor` in `app/src/state/session.svelte.ts:455-458` takes `item.full`, which is `sin(1)` for a DEG `sin(1)` (**verified** with `FACTS=1`; the key sequence in the app was not run). Right value: what the line showed when it was stored, sin(π/180) = 0.0174524064373 and atan(3/4) = 36.8698976458° (oracle, mpmath). **Fix:** G34. A Home value that leaves its evaluation (a stored value, Ans, a `\res` chip, the library export) must not depend on the angle mode. Use its angle-free exact form where Giac gives one, else the confirmed decimal marked inexact.
2. **A value made from `e^` in DEG is right only in DEG** (**verified**; G21). The pasexp helper (`app/src/engine/homeEval.ts:143-148`) returns `cos(16200/pi)+i*sin(16200/pi)`, an exact text that only DEG reads correctly. `A:=e^(i·90)` in DEG shows −0.448073616129+0.893996663601·i and stores `A:=(cos(16200/pi)+i*sin(16200/pi))`. In RAD, `A` gives −0.299515394755−0.954091467473·i ≈. `C:=e^(1+30i)` behaves the same way. The library export writes the same text under the description `// Z = -0.448073616129+0.893996663601*i`, and an import in RAD gives the wrong value. Right value: exp(90i) = −0.448073616129+0.893996663601i (oracle). **Fix:** G34 (the same rule as finding 1), and G21b (no helper at all).
3. **Home in DEG: `∫₀⁹⁰ e^(i·x) dx` gives `= 1+i`, marked exact** (**verified**). The rewrite turns the typed exp into pasexp(i·x), which returns exp(i·x) for a symbolic x. Giac then builds exp(90i) itself and reads it in degrees. Right value: −i·e^(90i)+i = 0.893996663601+1.44807361613i (derived; oracle). In RAD it is right. This is the case of decisions.md "G21" (pass 17), but in Home and with an `=`. **Fix:** G21b.
4. **A function defined in RAD, or imported from a library, ignores F29 in DEG** (**verified**). `gr(x):=e^(i·x)` typed in RAD stores `exp`, and in DEG `gr(90)` gives `= i`. A library file with `q(w):=exp(i*w)` behaves the same way, because `importLibrary` defines through `cas(d.text, defaultCasSettings)` in RAD (`app/src/engine/library.ts:290`). The rewrite (`host.ts:446`, `expIgnoresAngle`) touches only typed text. Right value (F29): −0.448073616129+0.893996663601i ≈. **Fix:** G21b. A Giac patch fixes every path at once; a text rewrite cannot.
5. **Units: a zero term skips the unit check** (**verified**; G16's design, docs/04 4.3 "an exact 0 has no dimension"; decisions.md's G16 default calls "terms that cancel exactly" a known gap, but no package holds it and `0 m + 1 s` is not even a cancellation). `0 m + 1 s` gives `= 1 s`. `5 m − 5 m + 1 s` gives `= 1 s`. `0 m → s` gives `= 0 s`. `0 ± 0.1 m` gives `0.00 ± 0.10` with no unit. `pasuq` (`app/src/units/evaluate.ts:32-36`) reads the dimension from `normal(f)`, where a term with value 0 has vanished. Right answer: refused with "Units don't match: L vs T" (derived: a sum of a length and a time has no dimension whatever the numbers), and `0 ± 0.1 m` keeps its m. **Fix:** G35. Check dimensions on the formula with every number before a slot replaced by its own positive symbol, as G18 already does for ± values, and only then put the numbers in.

## Part 2: limitations and oversights

1. **No test changes a setting between two lines.** Every golden and e2e case is one input in one setting. Findings 1–4 all need a sequence: store, switch, recall. G34 should add a small "sequence" form to `home.yaml` (inputs with settings per line) that later packages can reuse for Digits, FIX, the decimal comma (R57) and the angle mode.
2. **The rule that a carried value is setting-free was never written.** docs/04 2.4 says a stored value keeps its mark (M4-7), but not its value. The plan needs one sentence: a value that leaves an evaluation is the value shown, independent of every setting. G34 writes it into docs/04 2.8 (text in its report), in the space S10 frees.
3. **The G21 rewrite is the wrong level.** A text rewrite reaches what the user types, not what Giac builds, what was stored before, or what a library brings. Pass 17 already recommended G21b. With findings 3, 4 and 7 it is no longer optional, and F29 (decided) already says what the behaviour must be. So I settled the open "G21" item as a package (decisions.md). The owner's "would change if" (an error or ⚠ instead) contradicts F29 and needs his word to reopen.
4. **"An exact 0 has no dimension" (docs/04 4.3) made a mismatch silent.** It was written as a display note, but it is the hole of finding 5. G35 rewrites the sentence: the dimension is checked per term before the numbers go in; only the shown 0 has no unit when the terms cancel.
5. **The unit chain is still untested from the keys.** R24a's model, R28's parser and G16's evaluator agree when I join them by hand, but nothing joins them in the app until R24c. R24c's e2e must cover a zero term, a leading minus with ±, and a °C slot, so that its own review sees findings 5 and 13.
6. **The start chunk.** At 0.72 kB of headroom, R15c2 (new keys, the round pad) will likely need its own lazy split. Its file already asks for the delta; the order should let R15c1 measure first. If R15c1 adds more than 0.3 kB, an annabell or ron package must move something out first (the Settings page and `displayMode.ts` are candidates, 2.4 kB raw).
7. **Audit coverage.** The Opus passes look at three packages at a time and the Sonnet audits at one diff. Neither sees a cross-package path (exp + stored values + library export, R58 + the parser's e). This check is the first look at the whole since night 1. One such check per two nights is cheap insurance: at least one sofia pass "across the night" before a push.
8. **R58 and the G2 backbone.** G2 item 45 answered "Alpha T types t in CAS", so R58 follows the G2. What the G2 does with e and i on that layer is not known, and our parser's choice (e = Euler) was made when lower case cost Shift + Alpha. This is a new G2 question (decisions.md "R58: e and i").
9. **Decisions the code now makes obsolete.** decisions.md "G21" (settled here, see point 3). The brief's "the gorge lane has no open package" (rewritten here). R24c's "°C one flick up" stays, but only after the owner's answer on compounds (finding 12) will °C in a slot be useful beyond plain conversions.
