*Written 2026-10-12 after the architecture pass (docs/04), base `phase-1` at f87874a; sections 1–4 rewritten and sections 7–8 extended on 2026-10-15 at 3aa1a66 (architecture check). This is the advisor's map: how a key press, a number, a build and a check flow through the code, the engine behaviour learned by probing, and the traps where the docs and the code disagreed. Code moves: before relying on a line here, rerun the probe or the grep it names ([tools/probes/](../../tools/probes/README.md)). ## 1. A key press to a Home result

*Rewritten 2026-10-15 at 3aa1a66 (architecture check, docs/04 5.5).*

1. **Keypad** (`app/src/keyboard/Keypad.svelte`, `gestures.ts`): keys fire on release; a slide of 20 px up or down arms a flick (up = the Shift layer, down = the letter; R9, no hold time); the arrow pad is a trackpad (K1); ⌫ fires on touch and repeats while held, with pointer capture (R25b). Hiding the app, `pagehide` or a touch screen's window blur ends every gesture (`cancelAll()`, R25a).
2. **App.svelte `press()`**: Shift and Alpha toggle or lock; an open sheet takes the key first (`sheetPress`); keys pressed while an app loads wait, except a few (`AT_ONCE`). **`run()`**: `actionFor()` (`keyboard/keyboard.ts`) picks the layer's action from `spec/keyboard.yaml`; ▲ on an empty line picks a history row and the next keys act on it (`historyKey`: Enter inserts it, Menu and Shift + View act on it); specials go to `special()`; an app view takes its arrows; a b/c on an empty line cycles the last result's form (R10); an operator on an empty line inserts `\ans` first when a last result exists (`entry/ans.ts`, docs/04 2.8); everything else goes to `entry.run(action)`.
3. **EntryController.run** (`app/src/entry/controller.ts:279`; MathLive loads after the keypad, keys pressed before are queued): ▶ goes to the next empty box while one is ahead, stopping first at the end of the box that holds a template it leaves (`nextBox` in `stops.ts`, R43); ⌫ and Del go to `delete.ts` first (R23–R26h, "⌫ and Del keep a template whole"); ᴇ on an empty line is `1ᴇ`; 10ˣ after a digit is `×10^□` (R27a); a key whose template takes the term before it (`#@`) takes a whole E number, a chip, a fraction, root or power (L8, L9, R14); a selection is the key's argument, bracketed under a power or DMS unless it is one plain term (R17); after an arrow, `settle()` steps on to a place where a key types into a box (`stops.ts`, R27b). `delete.ts`, `boxes.ts`, `stops.ts` and `hwkeys.ts` load with MathLive, outside the start chunk.
4. **Hardware keys** (`entry/hwkeys.ts`, a capture `keydown` on the field, R26b, R31): a character a keypad key types presses that key through `press()`; `e` after a number's digits is ᴇ; Backspace, Delete and the arrows press ⌫, Del (Shift ⌫) and ◀ ▶ ▲ ▼; a letter goes to App's `typeLetter`, which runs `press()`'s checks (sheet, loading app, no entry line) before `entry.run` (R45, docs/04 5.5).
5. **Enter → `Session.submit(latex, …, chips)`** (`app/src/state/session.svelte.ts`): pushes a pending history item; Ans is resolved now, from the view's last result (`lastChip()`), into the chip table; then the parser chunk loads (`loadParser()`) and `latexToGiacInfo(latex, { chips })` gives the Giac text and whether an input was inexact.
6. **Parser** (`app/src/input/latex-to-giac.ts` → `parse.ts` → `emit.ts`): LaTeX → a JSON tree → Giac text. Accepts only what our keys produce; unknown input is an error, never guessed. Single letters multiply (`AB` → `A*B`), `f g h` and defined one-letter functions are calls, `\operatorname{name}(…)` passes any name through, chips (`\res{k}{…}`, `\ans`, `\const{ID}{…}`) become their table values as exact literals, `sin 7(2)` is refused (R27b). Owner: ron.
7. **Calc port → MathEngine** (`app/src/calc/engine.ts` → `engine/workerEngine.ts`): builds `HomeSettings` from the defaults plus digits and angle; posts to the Giac worker once the stored definitions are in (`define`, 3 s timeout); keeps the definitions log (G3) and stores it.
8. **Worker** (`engine/giac.worker.ts` → `createRequestHandler` → `EngineHost.home`, `host.ts`): sets Home mode once per settings change (cached by a mode key); `strict.eval` turns Giac's quiet `undef` plus a printed "syntax error" into a syntax error.
9. **homeEval** (`engine/homeEval.ts`, with `numeric.ts`): decimal literals → exact rationals (`toExactLiterals`) → `pasans:=(…)`. Paths: exact; exact-big (shown from the exact value, Ans becomes a 30-digit float); float-timeout and float-error (re-run at `workDigits`). The facts for the mark: `exactRational`, `reliableDigits` from the agreement check (P, P + 20, P + 40), `warn` for an unaudited float; `full` is the exact text up to 2 kB, else the P-digit decimal (`homeEval.ts:485`); a list or matrix carries `items`. A result that is not a number, or a list holding an open `==` or `≠` test, takes the symbolic path: Giac's text (regrouped unless it holds `==`, R18f3), drawn from Giac's `latex()` as in CAS, with no mark unless it holds a float: then `approximate` and `warn: "unchecked"`, so `⚠` without a count (G27, docs/04 2.3 #17).
10. **Back in the session** (`finish()`): the item stores `text`, `approximate`, `value`, `facts`, `rational`, `resultLatex`, the chip value `full` with `fullExact` (only when the text kept is ≤ 2 kB: `session.svelte.ts:446` takes `r.exact` first, docs/04 2.3 #18), and the line's `chips`; the history is saved 400 ms later.
11. **Display** (`state/displayMode.ts` `renderNumeric` and `markFor` → `engine/format.ts` `markOf`, `formatComplex` → `render/home.ts`): every row is re-formatted from `value` for the current digits and format (STD, SCI, ENG, FIX, PFX, or the item's own form: fraction, mixed, polar), only to its confirmed digits, with its mark `=`, `≈` or `⚠ n`. Drawn by MathLive's static renderer (`render/Math.svelte`).
12. **Reuse:** tapping a result, or ▲ then Enter, inserts a chip `\res{k}{shown}` whose value is `full` (`App.svelte` `insertResult`; an open `==` or `≠` test in a value is sent as the value test again, `input/chip-giac.ts`); without a chip (the text kept was over 2 kB) the drawn LaTeX goes in as typed (`render/insertable.ts`).

## 2. The other paths

- **CAS** (`host.ts` `cas()`): typed decimals become exact (P9, `toExactLiterals`), then `pcasans:=(…)` at `Digits` = the Home digits setting; `regroup` when the text has `*` and no `==` (R18f3); a result that is a number with a float comes back as `numeric` (a `HomeResult` with its facts: drawn and marked by our formatter); anything else is `latex(pcasans)` → `render/tidy.ts` → MathLive, and a float inside it is printed by Giac and marked `⚠` (`approximate`, `warn: "unchecked"`; G27, docs/04 2.3 #17).
- **Solve and Function analysis** (`engine/solve.ts`, `solve1.ts`, `analysis.ts`): work precision `max(30, digits+10)`; 1-D: bracket from the guess, Brent, else damped Newton, polish; systems: GSL `hybridsj`, `hybrids`, Giac Newton; polynomials: `proot` then Newton; every root substituted back (relative residual ≤ 1e-15, else ⚠) and compared after a second polish (M4-8). `keepingAns` and `withUnassigned` protect Home's Ans and the user's variables. Hard timeout 30 s. These views show only `⚠` (`calc/shown.ts`).
- **Num table** (`analysis.ts` `table()`): each cell is a full `homeEval` of `subst(f, x=…)`: same paths and facts as Home; the cell shows `⚠` when fewer digits are confirmed than shown.
- **Plot** (`apps/function/compile.ts`): the same parse tree → `emit-js.ts` → `new Function` for drawing in doubles; every number shown (trace, Num, analysis) comes from the engine.
- **Cancel** (`WorkerEngine.cancel`): terminate the worker, start a new one with `init.replay` = the definitions log. A worker crash takes the same path (`onerror`); a stored definition that crashes it every time loops (F31, G19). Budgets use Giac's own interrupt instead (patch 0002), which keeps the worker. *(The Python app, its MicroPython worker and the `calc` bridge were removed by P11, R5 and A5.)*

## 3. Start-up and state

- **Order** (`app/src/main.ts`): polyfills → mark `js-start` → `createCalc()` starts the Giac worker at once (D2) → Session → `shell.restorePlace()` → `restoreSettings()` → mount App → after two animation frames: mark `keyboard-ready`, load MathLive (808 kB) with `delete.ts`, `stops.ts` and `hwkeys.ts`, restore the history, then read the kept line (`entry`, R34; the field waits for it at most 1 s and puts it before the queued keys), reopen the last app. After the engine is ready and the browser idle: copy and paste (`loadClip`), then the service worker, which precaches the whole build. A capturing `focusin` listener drops any focus that lands while the app is away (R25c).
- **IndexedDB** (`state/storage.ts`, database `pascaline`, store `kv`): every value stamped with `DATA_VERSION` and migrated on read; `settings` (schema 2: digits 1–30, `pfx`; each field validated on restore), `view`, `place`, `history` (≤ 200 per view, with `full` and the chip table), `defs` (the definitions log, replayed at start, G3), `app.function`, `app.solve`, `entry` (the half-typed Home/CAS line `{ view, latex, chips }`, `entry/keep.ts`: written on hide once the line is settled, cleared by every clear of the line; F30, R34), `userKeys` (the free keys' slots, `keyboard/userKeys.svelte.ts`, R15b).
- **Bytes** (`npx vite build --outDir <scratch>` in `app/`, then `node scripts/size-check.ts <scratch>`, 2026-10-15 at 3aa1a66): start chunk 151.94 kB raw, 53.01 kB gzip (budget 156 / 54), MathLive 807.73 kB, the parser chunk 25.6 kB, `delete.ts` 15 kB, Function 22.5 kB, Solve 10.9 kB, JSXGraph chunk 1,035 kB, Giac wasm 9.75 MB, precache 12.3 MB. ## 5. Giac behaviour learned by probing (dev build, Giac 2.1.0 + GSL)

- **Precision switch:** at `Digits` ≤ 14 floats are doubles, above that MPFR. `evalf(x,40)` therefore depends on the global `Digits` for functions without an MPFR path: `BesselJ`, `Airy_Ai` give a double at `Digits:=12` and "Bad Argument Value" at `Digits:=30`.
- **Floats on the "exact" path:** `normald_icdf`, `romberg`, `nInt`, `fsolve`, `BesselJ` return floats even in exact evaluation, so Home's `exact` text is a float string and the 40-digit `evalf` returns the same double.
- **Accuracy traps:** `normald_icdf(10^-10)` is wrong from the 8th digit on both paths (−6.36134035799 at 12 digits, −6.3613403515334 at 30; true −6.36134090240…); `normald_cdf` is right in the tail, and `fsolve(normald_cdf(x)=10^-10, x=<guess>)` at `Digits:=40` gives 32 correct digits. `UTPN(10)` loses about 23 digits to cancellation in `1-erf` at 40 digits. `evalf(sin(10^22))` at 12 digits gives −0.54764225985 (wrong), MPFR gives the right −0.8522008497671888.
- **Binary decimals:** `1-0.9-0.1` is `1.7763568394e-15` at `Digits:=12` and `2.96e-31` at 30; only exact literals give 0 (that is why Home converts them).
- **Text forms:** parse errors return `undef` and print "syntax error"; `solve` returns `list[…]`; lists and matrices print with exact fractions; `infinity` for `1/0`; `x*x` stays unless `regroup`; floats print at `Digits`.
- **Names:** an identifier with an underscore can read as a unit (`pas_d`), so our internal names have none; `x_1` is a plain identifier; `0xFF` and `0b1011` are read as numbers, `hexa()` stays unevaluated, `bitand`/`bitor`/`bitxor` work.
- **Help data:** `doc/aide_cas`: 1,780 entries (`# name`), lines `1` French (not GPL, never ship), `2` English, `0` argument types, `-1` related commands, then examples; 211 entries are Giac's own units and constants (`_kph`, `_c_`), which we do not use.

## 6. libqalculate behaviour learned by probing (5.13.1, spike libraries)

- **API:** `Calculator::calculate(str, eo)` (untimed) works on the calling thread; the timed `calculate(MathStructure*, str, msecs, …)` answers "aborted" with `msecs = 0`. `separateToExpression` splits `… to unit`; `convert(m, to, eo)` converts; `MathStructure::isApproximate()` and `PrintOptions::is_approximate` report approximation; `setPrecision(n)` sets the working digits.
- **Exactness:** the default `APPROXIMATION_TRY_EXACT` gives exact rationals for SI-defined factors (`72 km/h to m/s` = 20, `1 in to mm` = 127/5, `1 lbf to N` = 8896443230521/2000000000000) and flags π, logarithms and uncertainties as approximate.
- **Silent non-answers:** `1 m + 1 s` returns `1 m + 1 s`; `20 °C * 2` returns 40 °C; `hp` is 745.699987158 W, flagged exact (true 745.69987158227 W).
- **Names:** `degC` → coulomb·degree, `BTU` → byte·tesla·…, `mu0` → 0 kg, `epsilon0` → 0 J·bit, `NA` → N·A, `R` → röntgen, `h` → hour, `g` → gram, `e` → Euler's number. The real names: `°C`/`oC`, `Btu`, `magnetic_constant`/`μ_0`/`mu_0`, `electric_constant`/`ε_0`/`epsilon_0`, `elementary_charge`, `k_B`, `planck`, `c`.
- **Data files:** `units.xml.in` has 426 unit definitions (a count of `<unit` gives 982 because of nested references), `variables.xml.in` 166 constants plus 18 built-in, `prefixes.xml.in` 34; names carry flags before `:` (`ar:c,speed_of_light`, `au:Ω,r:ohm,p:ohms`); constants have a `uncertainty` attribute; some are formulas (μ₀ = 2hα/(c e²)), which need qalc to evaluate.

## 7. MathLive behaviour learned by probing (0.111.1, Playwright Pixel 7 profile, 2026-10-14)

- **Focus is late:** `onFocus` focuses the hidden keyboard sink (a `SPAN`) 60 ms after `mf.focus()`, so a test must wait about 150 ms before it reads the focus.
- **Focus restore:** `MathfieldElement.restoreFocusWhenDocumentFocused` (default on). Every blur of the field arms "next window `blur`, then next window `focus`: focus the field", and only a document `focusin` or `click` disarms it. That brings the system keyboard back on Android (backlog F9).
- **⌫ at a bracket:** `onDelete` on a `\left…\right` pair, with the cursor at the start of its body, sets the opening bracket to `.` while the closing one is real, and moves nothing. The next ⌫ does the same again, so the line is stuck (backlog F10). Del at the end of a body is the mirror: `\left(2‸\right)` Del → `\left(2\right.` and stuck. Minimal case for upstream: value `\left(2\right)`, position 1, `deleteBackward` three times → `\left.2\right)` each time, position 1. Our way around it: `app/src/entry/delete.ts` (R23). A pair that holds only a placeholder is removed whole instead (`\log\left(\log\left(□\right)\right)` ⌫ → `\log\left(\log\right)`). ⌫ at the start of a root or a box dissolves it and keeps the content.
- **A focus cannot be taken back during its 60 ms:** `focus()` on a blurred field sets it "focused" at once and starts the timer. Nothing in the public API cancels it: `blur()` finds no focused sink, and `onBlur` returns early while `focusBlurInProgress` is set. So a `dropFocus` in those 60 ms is undone (`mathlive.mjs` 40255–40303). The app catches the late focus when it lands instead: a capturing `focusin` listener on `document` in `app/src/main.ts` drops it while the app is away (`focusin` is composed, so it arrives from MathLive's shadow root; R25c, backlog F13).
- **⌫ per kind of template** (`onDelete`, `mathlive.mjs` 31706–31870; probe over all 32 templates, 2026-10-14; backlog F15–F21):
  - **Bracket pairs:** ⌫ right after the pair sets the closing bracket to `.` and moves into the body. The `)` disappears and the line reads `sin(2`. Our way around it: `stepIn()` in `app/src/entry/delete.ts` (R26c) moves into the body and deletes nothing; a body ⌫ empties shows □ (`keepBox()`).
  - **Roots (`surd`):**
    - ⌫ at the start of the body dissolves the root and keeps its content: `5√(‸23)` → `523`.
    - An index emptied by ⌫ disappears from the LaTeX: `\sqrt[3]{8}` minus the 3 is `\sqrt8`, and Enter computes √8.
    - ⌫ at the start of the index leaves the root and puts the cursor before it.
    - Our way around it: `deleteAtBoxes()` (R26e).
  - **Fractions (`genfrac`):** ⌫ at the start of the denominator joins both parts (`\frac{5}{23}` → `523`). At the start of the numerator it steps out before the fraction. Our way around it: `deleteAtBoxes()` (R26e).
  - **Powers:** an exponent is an atom of its own (`^…`, its box one level deeper) right after its base. ⌫ at the start of the exponent steps out after the base, and the next ⌫ deletes the base and leaves the exponent on whatever stands before it. Del at the end of a base deletes the whole exponent with its content (`5‸^{23}` → `5`), and Del before a one-atom base deletes both (`‸5^{3}` → empty). Our way around it: `deleteAtPower()` (R26d).
  - **A selection that is all of a pair's body:** MathLive's delete removes the pair with it (`keepSelectedBox()`, R26d).
  - **Limits, ∫ Σ Π (`subsup`, `extensible-symbol`):**
    - ⌫ at the start of a script steps out to just after the base. The next ⌫ deletes the base, and the script stays as an orphan `^{…}` that sticks to whatever comes before it.
    - A script emptied by ⌫ is removed.
    - ∫'s integrand and variable are not branches: they stand on the operator's own level, after it (`\mathrm{d}` is one atom, `\,` another). Our way around it: `bigOp()` through `deleteAtBoxes()` (R26f).
  - **`\log` and `\ln`:** any ⌫ inside their subscript deletes the whole operator (line 31863). Our way around it: `inLogBase()` selects the one atom and deletes the selection, which goes through `deleteRange` (R26h).
  - **Arrays (matrix, piecewise):** ⌫ at the start of a cell does nothing. ⌫ right after the array deletes it whole. Each cell is a branch of the array atom, in reading order, from its empty sentinel one level deeper; piecewise's condition cells start with the three atoms `\text{i}`, `\text{f}`, `\text{ }`. Our way around it: `table()` through `deleteAtBoxes()` (R26g).
  - **EQ, DMS, evaluate-at:** EQ's comma and evaluate-at's = are plain atoms in their branch; DMS stands on the line itself, ° ′ ″ plain atoms, its degrees with no left edge in the LaTeX; the key takes the number before it as its degrees (`#@`, R27a). Evaluate-at is a `\left.…\right|` pair and a subscript atom right after it. Our way around it: `equation()`, `dmsAt()`, `evalAt()` through `deleteAtBoxes()` (R26h).
- **A placeholder is an atom:** ⌫ in an empty box deletes the □ itself, so the box leaves the LaTeX (`EQ(,□)`, `\lim_{\to□}`, a matrix cell with nothing in it). The last atom of a fraction's part is followed by the next part's sentinel on the same level, not by a lower one (`endsBox()`).
- **Hardware keys take the keypad's path** (R26b, R31): Backspace, Delete and every printable ASCII key go through `app/src/entry/hwkeys.ts` (a capture `keydown` on the field, loaded with MathLive). A character a keypad key types presses that key through App `press`; `e`/`E` after a number's digits is ᴇ; Backspace, Delete and the arrows are ⌫, Del and ◀ ▶ ▲ ▼ (R45; Shift + arrows, Home and End stay with MathLive); a letter goes through App `typeLetter` (an open sheet filters with it, a loading app queues it); characters no key types do nothing. Enter presses the keypad's Enter and Escape is caught by the controller; Ctrl/Alt/Meta combinations and non-ASCII characters still go to MathLive.
- **◀ and ▶ visit every offset in MathLive:** between a function name and its `\left`, inside `\operatorname{…}` and `\text{if }`, around ∫'s `\mathrm{d}`. Our arrows and the trackpad skip them (`app/src/entry/stops.ts`, R27b); a tap can still land there, and the parser refuses `\sin7\left(2\right)`. Right after a `\text` atom MathLive's mode is text, so a typed key goes into the text unless the field is switched to maths first (`run` does).
- **A typed key takes its neighbour's style:** MathLive's default `onInsertStyle` copies the style of the atom on one side. Which side depends on a hidden style bias that changes with how the cursor arrived. So a 7 next to `\mathrm{i}` became `\mathrm{i7}` or `\mathrm{7i}`. Our field sets `onInsertStyle = () => ({})` (R27c; `null` throws in 0.111.1).
- **▶ and the end of a box:** while `\placeholder` appears after the cursor, ▶ is `moveToNextPlaceholder`, except when the plain step leaves a template and lands at the end of a box (`endsBox()`), where it stops (R43, F34). With a □ selected, `mf.position` is the selection's end. A □ is one stop: moving onto it selects it.
- **A finger tap places the caret twice** (2026-10-15, backlog F33):
  - `onPointerDown` (`mathlive.mjs` 34364) places it with `offsetFromPoint`, the same for mouse and touch, and that is right.
  - On the lift, for touch only, the window `pointerup` of `MathfieldElement.onPointerDown` places it again (line 41468), from `atomBoundsCache` bounds that are out of date after the first move. At the right edge of a fraction, root, power or bracket it lands at the start of the line or of the box.
  - A mouse never takes the second path, so desktop tests miss it: compare `page.touchscreen.tap` with `page.mouse.click` at the same point.
- **Prompts in a read-only field** (the unit slots, docs/04 4.3; throwaway probe 2026-10-15): `\placeholder[id]{}` per slot; `setPromptValue` takes `\frac{\mathrm{km}}{\mathrm{h}}`, `\mathrm{m}^{2}`, a product, `\sqrt{…}` and a prefixed unit, and `getPromptValue` gives them back (normalised: `^{2}` → `^2`, and `\mathrm{k}\mathrm{\Omega}` → `\mathrm{k\Omega}`). `moveToNextChar` goes from prompt to prompt and never into the formula. `insert()` with the caret outside every prompt still edits the read-only formula. An empty prompt's range is one position (`getPromptRange` → `[3,3]`).
- **Probing the entry:** a scratch spec in `app/test/` that taps keys and logs `window.pascaline.entry.value` after each one (helpers `tap`, `drag`, `touch` in `app/test/helpers.ts`; `?engine=fake` is enough for the entry). Delete it afterwards.
  - To check every template, drive `window.pascaline.entry.run({kind, …})` (the key path).
  - To read each line state as the parser does, call `(await import("/src/input/parser.ts")).loadParser()` inside `page.evaluate`, then `latexToGiacInfo(value, { chips: {} })`.
  - To simulate leaving the app, redefine `document.hidden` and dispatch `visibilitychange` and the window `blur` and `focus` events (`leaveAndReturn` in `app/test/softkeyboard.spec.ts`).
  - Write the results with `writeFileSync` from the test, since `console.log` from the page is not shown.
  - For taps, set the line again and wait 550 ms before each one: MathLive counts a tap within 5 px and 500 ms of the last one as a double tap, which selects a group.

  R26a turns the template probe into a test.

## 8. Where docs and code disagreed (2026-10-12), and the lesson

- The "L7 size test" named in plans did not exist.
- docs/03 listed `Ans` in Home; no key or parser rule reaches it.
- docs/03 said 982 units; there are 426 definitions.
- `rules.md` gave the parser to gorge; ron's agent file, 03 section 8 and the git history give it to ron.
- `rules.md` said "two principles" after CLAUDE.md had three.

**2026-10-15 (architecture check after 4a's entry work):** sections 1–4 here still described the Python app, inserted results as rounded digits, unstored definitions, digits ≤ 15 and the 2026-10-12 sizes; docs/04 2.4 said "no mark for non-numbers" while 2.9 said every CAS float gets `≈` (the code follows 2.4, so `x-0.54764225985` goes unmarked, docs/04 2.3 #17); docs/04 2.4 promised a reader for `tieRisk` that was never built (and is not needed); R43's text proposed a fourth test for "the end of a box" beside the three in the code (docs/04 5.5); docs/04 section 4 still described the qalc worker after P15; `app/scripts/size-check.ts` still names a "Units app chunk" (P11: the unit view). All fixed in the docs except the size-check label (annabell, with A6) and CLAUDE.md's "Worker 3: libqalculate" line (G15's merge gives the text).

**Lesson:** check claims in the code, the engine and the data, never in the docs alone; cite `file:line` or a probe; mark the rest (to verify) with who checks it and how.

## 9. How to check a claim quickly

| Question | How |
