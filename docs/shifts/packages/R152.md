- A history row shows `\exponentialE` and `\imaginaryI` as raw LaTeX in red where the entry line drew e and i.
- Cause: `app/src/render/Math.svelte:21` calls `convertLatexToMarkup(latex, { macros: ENTRY_MACROS })`. MathLive's `macros` option replaces its own macro table, and `\exponentialE`, `\imaginaryI` (and the rest of that table) are macros there. Checked in Node: `\exponentialE^{\imaginaryI\pi}` draws without the option and is raw with any `macros`.
- The entry line does it right: `app/src/entry/field.ts:112` merges, `mf.macros = { ...mf.macros, ...ENTRY_MACROS }`. `app/src/units/open.ts:196` reuses the field's table.
- Why no test caught it: `app/src/entry/macros.test.ts` checks the chips with `{ macros }` and no e or i; `Math.test.ts` uses a stand-in for MathLive.
**Read:** `app/src/render/Math.svelte`; `app/src/render/mathlive.svelte.ts` (what `mathlive.mod` holds); `app/src/entry/macros.ts`, `macros.test.ts`; `app/src/entry/field.ts:100-115`; `app/src/views/History.svelte`; the pinned MathLive's typings (`app/package.json`) for where its default macros are exported.
