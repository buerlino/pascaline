### annabell, A50: an older build never overwrites newer data, branch `p1/annabell-storagedown`
**Lane:** night-safe (no device). **Opus** (stored data under every later package, P17), audit Opus. **Starts when:** now; before A43 (which tests an upgrade on the device); both before A7 (owner, 2026-10-29).
**Why:** (`app/src/state/storage.ts`, phase-1 `fa52380`) `unstamp` (lines 49–58) returns a record from a newer DATA_VERSION as it is, so an older build can read it; but `kvSet` (91–103) stamps every write with its own DATA_VERSION, so the older build's next save of that key replaces the newer record under an older stamp, and the next upgrade runs its migration steps again over data already migrated (G46's step, `app/src/engine/angleMigration.ts`, is not known to be safe twice). Downgrades happen: the web's kill switch (A49), an older APK installed again, the night's device moving between builds.

**Read:** `app/src/state/storage.ts` and its tests; `app/src/engine/angleMigration.ts` and its tests; decisions.md "Stored data carries a version; one signing key".

1. **Tests first (vitest), failing on phase-1:** a stored record stamped DATA_VERSION + 1 survives a `kvSet` of the same key from today's code (an in-memory IndexedDB stand-in as the existing tests use; no new dependency); every step of MIGRATIONS applied to its own output changes nothing; a record without a stamp goes through every step exactly once.
2. **The change:** `kvSet` reads the stored stamp in the same readwrite transaction and does not write over a newer one (the session keeps its value in memory); a migration step that the test shows unsafe twice is made safe. The DB name, the store and DATA_VERSION stay.

**Done when:**
- The new tests fail on phase-1 and pass; typecheck, vitest, e2e.
