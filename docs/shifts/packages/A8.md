0. **The tag check takes a test tag** (owner, 2026-11-03): `tools/check-version.sh` accepts `vX.Y.Z` and `vX.Y.Z-<suffix>` (suffix `[0-9A-Za-z.]+`) and compares only X.Y.Z with the three files; the usage text and `build.sh`'s `--release` comment say so. Cases first in `tools/check-version.test.sh`, failing before the change: `v0.1.0-test` passes, `v0.1.0` still passes, `v0.0.1-test` fails (mismatch, exit 1), `v0.1.0-` and `v0.1.0-a b` fail (usage, exit 2). The release workflow, `build.sh --release` (`PASCALINE_RELEASE_TAG`) and `pages.yml`'s tag run all call it with the tag.
1. **Tests first:** a workflow skeleton with the triggers, `permissions` and `concurrency` passes `actionlint` (run once with `npx` or a container; not added to the repo) before any step is added, and is checked again after each one.
2. **The workflow:** `.github/workflows/release.yml`: trigger `push` of tags `v*` and `workflow_dispatch` with a tag input; runner `ubuntu-24.04` (podman); `permissions: contents: write`, nothing more; `concurrency` per tag; `timeout-minutes: 120`; every action pinned to a full commit SHA with the version in a comment (checkout, setup-java 21, setup-node 22), no other third-party action; the release created with `gh release create` and `GITHUB_TOKEN`. Steps in order: (1) `tools/check-version.sh "$GITHUB_REF_NAME"`; (2) engine and qalc in the pinned container with `NO_LOCK=1`; (3) the golden gate on `engine/giac/_out/release` (absolute `GIAC_OUT`), which must print `GOLDEN GATE PASSED` before the key is decoded; (4) decode the keystore into `$RUNNER_TEMP` (mode 600), then `NO_LOCK=1 ./build.sh --release --engine-dir … --qalc-dir …` with the secrets as `env:` of this step only, never in a `run:` line or `echo`, and an `if: always()` step that deletes the keystore; (5) `gh release create "$TAG" dist/pascaline-<v>.apk dist/pascaline-<v>.apk.sha256 --prerelease` when the major version is 0 or the tag has a `-`, with notes giving the commit, the engine and qalc `SHA256SUMS` and the certificate fingerprint. **The website stays out of a test:** `.github/workflows/pages.yml` runs on every tag `v*`, so the test tag would put a test build on pascaline-calc.org; its tag runs skip the build and the deploy when the tag name holds a `-` (a job-level `if:` on `github.ref_name`; `workflow_dispatch` and the kill run unchanged), and `app/scripts/pages.test.ts` (A45's pin test) pins that `if:`. Not in this package: the PR/CI checks (backlog C3, which builds on A6) and the F-Droid submission (C4).
3. **The checklist:** `docs/release.md`, the owner's one page: bump versionCode and versionName (and the F-Droid draft) in one commit on phase-1, `master` fast-forwarded to it and both pushed (`master` follows phase-1 since 2026-11-03); `git tag -s vX.Y.Z` (or `-a`); `git push origin vX.Y.Z`; watch the run; check the SHA-256 and `apksigner verify --print-certs` on the downloaded APK; install over the last release; what a failed run leaves behind (nothing is published) and how to re-run.
