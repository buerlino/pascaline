### annabell, A8: the release workflow, branch `p1/annabell-releaseci`
**Lane:** day (the owner pushes the test tag). **Opus** (it handles the signing key on a machine we do not own). **Starts when:** A7 is merged.
**Read:** decisions.md "The release path"; A7's report (the secret names); `build.sh` (after A7); `engine/giac/build-wasm-release.sh` and `engine/qalc/build-wasm.sh` (`CONTAINER_ENGINE`, `NO_LOCK`); `app/scripts/golden.ts`; `tools/check-version.sh`.
1. **Tests first:** a workflow skeleton with the triggers, `permissions` and `concurrency` passes `actionlint` (run once with `npx` or a container; not added to the repo) before any step is added, and is checked again after each one.
2. **The workflow:** `.github/workflows/release.yml`: trigger `push` of tags `v*` and `workflow_dispatch` with a tag input; runner `ubuntu-24.04` (podman); `permissions: contents: write`, nothing more; `concurrency` per tag; `timeout-minutes: 120`; every action pinned to a full commit SHA with the version in a comment (checkout, setup-java 21, setup-node 22), no other third-party action; the release created with `gh release create` and `GITHUB_TOKEN`. Steps in order: (1) `tools/check-version.sh "$GITHUB_REF_NAME"`; (2) engine and qalc in the pinned container with `NO_LOCK=1`; (3) the golden gate on `engine/giac/_out/release` (absolute `GIAC_OUT`), which must print `GOLDEN GATE PASSED` before the key is decoded; (4) decode the keystore into `$RUNNER_TEMP` (mode 600), then `NO_LOCK=1 ./build.sh --release --engine-dir … --qalc-dir …` with the secrets as `env:` of this step only, never in a `run:` line or `echo`, and an `if: always()` step that deletes the keystore; (5) `gh release create "$TAG" dist/pascaline-<v>.apk dist/pascaline-<v>.apk.sha256 --prerelease` when the major version is 0 or the tag has a `-`, with notes giving the commit, the engine and qalc `SHA256SUMS` and the certificate fingerprint. Not in this package: the PR/CI checks (backlog C3, which builds on A6) and the F-Droid submission (C4).
3. **The checklist:** `docs/release.md`, the owner's one page: bump versionCode and versionName (and the F-Droid draft) in one commit on `master`; `git tag -s vX.Y.Z` (or `-a`); `git push origin vX.Y.Z`; watch the run; check the SHA-256 and `apksigner verify --print-certs` on the downloaded APK; install over the last release; what a failed run leaves behind (nothing is published) and how to re-run.
**Done when:**
- The workflow passes `actionlint` (run once with `npx` or a container; not added to the repo); the run's log lines are in the report.
- On a throwaway tag `v0.0.1-test` from a test branch (the owner's OK, and the owner pushes it), the run ends with a pre-release whose APK verifies against `android/release-cert.sha256`; then the test release and tag are deleted. Then the owner pushes `v0.1.0`.
