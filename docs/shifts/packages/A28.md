No patch has gone through the pipeline yet (the patches last changed on 2026-10-11).
1. **Tests first:** in `scripts/pipeline.test.sh`:
   - A dry run on a branch that changes `engine/giac/patches/` prints an engine build step with its key, and `GIAC_OUT` for the worker and the checks points at that build.
   - A dry run on a branch without engine changes keeps the shared engine.
   - A run whose key differs from the shared engine's stamp prints the rebuild before the worker starts.
   All three fail on phase-1.
2. **The key:** a hash of the engine's inputs (`engine/giac/build-wasm.sh`, `engine/giac/patches/`, `engine/giac/wasm/`). A build is made once per key with `build-wasm.sh` under `tools/devlock.sh acquire host-cpu`, into a directory per key under `$main/engine/giac/_out/` (reused by the fix rounds and by a later run with the same key). It carries a stamp file with its key.
3. **The run:** when the branch's key differs from phase-1's, the worker, the fix rounds and the checks get `GIAC_OUT` set to the branch's build. A failed build ends the run as `NOT MERGED (engine build: …)`, not as a fix round.
4. **After the merge:** when the merge changed the key, `$main/engine/giac/_out/gsl` becomes that build: an atomic rename, with the old engine kept as `gsl.prev`. The log line names the key and the sha256 of `giac.wasm`.
5. **At every start:** when phase-1's key differs from the shared engine's stamp (after a merge by hand, say), the shared engine is rebuilt first, so no run checks against an engine that phase-1 lacks.
