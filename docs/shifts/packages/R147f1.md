### ron, R147f1: a tap on a history input keeps the focus in the entry line, branch `p1/ron-tappickfocus`
**Lane:** A, night (first: it fixes merged code before v0.1.0), Sonnet. **Starts when:** –. From Opus pass 89's FIX (repeated by pass 90; the night of 11-07 closed before it ran).
**Why:** (pass 89's probe on phase-1 0fb5bab0, Playwright, chromium-phone)
- Since R147 the first tap on a history row's input only picks the row. `app/src/views/History.svelte` (the `.in` button, about line 211) has no `onpointerdown` handler, while the `.result` button calls `preventDefault` there.
- A mouse click or tap on an input therefore moves the focus from the entry line to that button, and nothing gives it back. Before R147 the recall did, because the entry's `set` focuses the field.
- Probe: enter 7 and 8, then click the last `.in`. The active element is `BUTTON.in`. A hardware 5 types nothing and the row stays picked; a hardware Escape leaves the pick; a hardware Enter clicks the focused button and recalls 8 onto the line, where ▲ then Enter inserts a chip. A click on a `.result` keeps the focus in `MATH-FIELD`, and a hardware 5 drops the pick and types 5.
**Read:** `app/src/views/History.svelte` (the `.in` and `.result` buttons, `tapRow`); `app/src/views/pickRows.ts` (`rowTap`); `app/test/tappick.spec.ts`; `app/test/hwpaste.spec.ts`; `app/test/rows.spec.ts`.
1. **Tests first, red on phase-1,** in `app/test/tappick.spec.ts`: a click on an input picks its row with the focus still in the entry field; then a hardware 5 drops the pick and types 5; a hardware Escape drops the pick; a hardware Enter on an input picked by a tap inserts its result as a chip, as after ▲.
2. **The fix:** give the `.in` button the same `onpointerdown` `preventDefault` as the `.result` button, so the field keeps the focus. Check that the long press and the 40 px scroll drag in `tappick.spec.ts` still behave.
