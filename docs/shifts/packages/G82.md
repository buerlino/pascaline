### gorge, G82: Home's budget counts steps, not milliseconds, branch `p1/gorge-stepbudget`
**Lane:** night-safe (Opus worker; engine patch, golden gate). **Starts when:** G103 is merged (the exact pass reads its value through `giac_value` then; S23). The owner's A20 decision (2026-10-20): the Tab One's WebView and the desktop gave different results for 16 of 579 golden cases (29 findings), all of them from the Home budget of 300 ms running out sooner on the slower device. None of them came from WebAssembly, `BigInt` or `Intl`. A result must not depend on the speed of the device.
**Read:** decisions.md "A20" and "P19"; `engine/giac/patches/README.md` (0002, the sub-second clock); `tests/engine/interrupt-test.mjs`; `app/src/engine/homeEval.ts` (`budgetMs` near line 72, the `timeout` command near 262, the float fall-back near 655); A20's report (the 16 inputs).
1. **Tests first:**
   - a canary in `tests/engine/` that runs one heavy input (`sum((10001/10000)^k,k,1,2000)`) under a step budget twice and gets the same count and the same interrupt both times. It fails on phase-1 (no setting).
   - a golden-gate check: the A20 inputs give the same display, mark and digits under a step budget whether the engine is slowed or not (a busy loop in the test, or `ckevery` with a slowed clock). It also fails on phase-1.
2. **The patch** (P19; the next free number when it starts: 0003 is G75's): Giac's interrupt check (`control_c`, where 0002 compares milliseconds) can also count its own calls and interrupt after N of them. A new setting turns that on; the worker picks its name and records it in the patches README. With the setting off, Giac behaves as it does today (`timeout` stays a clock). Upstream link for B. Parisse in the commit.
3. **The count:** a probe (`tools/probes/`) runs A20's 16 inputs and the golden Home stage on the desktop and prints the number of checks each one uses. It also prints the count that equals today's 300 ms on the desktop (the slowest exact pass that passes today, with a margin). The same count must come out on two repeat runs. Home takes that count; `budgetMs` becomes a step count in `HomeSettings` (its name and docs/04 2.5 say so).
4. **What stays a clock:** the CAS view's 10 s before Cancel is made prominent (`CAS_SOFT_BUDGET_MS`), its safety net `hardTimeoutS` and Solve's hard timeout (`SOLVE_HARD_TIMEOUT_S`). These are limits a person waits on; they do not choose which path computes the result. A hang that never reaches the check is still stopped by Cancel.
5. **Docs:** docs/04 2.5 (the exact pass's budget is a step count, with the reason); the patches README row.
**Done when:**
- The canary and the gate check pass; `npm run golden` ends in GOLDEN GATE PASSED with no expected value changed, or each change is listed with its input under "Needs a decision".
- On the desktop, Home's Enter p95 has not moved by more than 10 % (numbers in the report).
- The report names the follow-up: annabell runs A20 again on the Tab One (`?bench=golden`), and the 29 findings are gone. A finding that remains goes under "Needs the user".
