### gorge, G116: the engine fuzzer: the oracle sweep at the edges, a new seed each night, branch `p1/gorge-fuzz`
**Lane:** night-safe (Opus; tools, tests and golden cases; no engine patch, no app code). **Starts when:** P23 has ended (owner, 2026-10-27: a differential fuzzer for the engine). Also r16's end mark (a 50,000-input sweep with no new false mark; not met, backlog "The hardening without a bug line").
**Why:** G61's oracle sweep (`app/scripts/sweep.ts`, `tools/probes/sweep/`) already judges random keyboard-LaTeX trees in Home against mpmath at 60 and 100 digits, RAD and DEG, 12 and 30 digits ("does the mark tell the truth"). Its leaves are mild (integers to 12, a few decimals, ᴇ±22, n! to 10!), so it rarely reaches where Giac goes wrong: F111–F114 and F113 (`atan(cos(0.001))` = 45 marked `=`) came from S16's hand-made inputs. Its `--nightly` mode (a seed from the day number, report only) has never run in a night. The gate's fixed seed must not move; one mode, not two.
**Read:** `app/scripts/sweep.ts`; `tools/probes/sweep/gen.ts`, `judge.ts`, `run.ts`, `oracle.py`; `app/scripts/sweep.test.ts`; `tests/golden/sweep-known.yaml`; `tests/golden/README.md` (the venv; `status: "pending"`); `tests/golden/oracle.py`; `docs/research/bug-patterns.md` families 3–6; backlog G94 (depth-3 trees crash the in-process engine).
1. **Tests first, failing on phase-1** (`sweep.test.ts`, pure, no engine): the edge generator (`--edges`) is deterministic for a seed and differs for another; 2,000 trees of one seed hold every leaf class of step 2 at least once; a sample of trees' mpmath texts evaluates in the sweep oracle's namespace; the gate's trees for seed 20261021 are byte-identical to phase-1's.
2. **The edge generator** (`tools/probes/sweep/edges.ts` beside `gen.ts`, the same `Case` shape; `gen.ts` unchanged). Leaves: near branch cuts and singular points (±1 ± 10^-k for k = 3, 6, 9, 15; cos(π/N) and sin(π/2 − π/N) for N = 10^3 … 10^8; 0 ± 10^-k; π/2 ± 10^-k, and 90 ± 10^-k for DEG; negative reals under √, ln and acosh); integers (0, ±1, 2^31, 2^53 ± 1, 10^20 + 1, 30!); huge and tiny magnitudes (1ᴇ±300, 1ᴇ±1000, 10^50 as a power). Functions: those of `gen.ts` plus acosh, atanh, |·|, x^y and the cube root. Depth up to 3, the same operator mix.
3. **The nightly mode at the edges** (no new mode): `node scripts/sweep.ts --nightly --edges [--seed N] [--count N]`. `--edges` takes the edge generator (default 5,000 trees, both angles, 12 and 30 digits); `--nightly`'s default seed becomes the clock, printed first so a run can be repeated. In `--nightly`, an engine crash (G94) restarts the engine and is a `crash` row with its input, never the end of the run, and the run writes the main checkout's `.tasks/sweep-<date>-<seed>.md`: one row per failure not in `sweep-known.yaml`, grouped by check, with the LaTeX, the answer and mark shown, the oracle's value and the smallest subtree that still fails the same check (try each child, keep the smallest). Report only: exit 0.
4. **The first run and its triage:** `--nightly --edges` at 5,000, then once more (two seeds). Group the rows by cause (one Giac call or one rule of ours; the smallest subtree shows it). A silent wrong number or a mark that lies (checks `=`, `≈`, `⚠n`, `part`, `novalue`) becomes a golden case in `tests/golden/precision.yaml` (value from `tests/golden/oracle.py`, never from memory; `status: "pending"`; the note names its backlog id) and a backlog line. A hang, a crash or a refusal where a value exists gets a backlog line only. A row an open line already covers (F61, F62, F86, F111–F114, G94) takes that id. **Never edit `docs/backlog.md`** (it is at its budget, and rules section 5): the new lines (ids from F119: input, shown, right, family) go in the report under "For shared files", at most five, ranked by reach; the rest stay in the `.tasks` file the report names. The Opus pass applies them within the budget.
**Done when:**

- The report gives both seeds, the count per check, at most five backlog lines under "For shared files", the path of the full `.tasks` file, and the time per 1,000 trees (to size the nightly step from 2026-10-28).
