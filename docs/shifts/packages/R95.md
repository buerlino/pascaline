**Why:** (night review 2026-10-30, fh-2 = bu-4, confirmed by both verifiers; S1 for the web build, no reach in the APK; base `bb90a5e`) Two tabs, or the installed PWA and a tab, overwrite each other's definitions and history.
- Every store key is written whole from the tab's memory: history (`state/session.svelte.ts:727-737`, also on `pagehide` and `visibilitychange`, `main.ts:70-75`, so the tab hidden last wins); definitions (`engine/workerEngine.ts:157-165`, the log read once at start, `:141-156`; `calc/index.ts:15`); settings (`session.svelte.ts:763-765`); user keys (`keyboard/userKeys.svelte.ts:137`); the apps (`apps/function/app.svelte.ts:559`, `apps/solve/app.svelte.ts:422`).
- No coordination: `grep -rn "BroadcastChannel\|navigator.locks\|onversionchange" app/src` finds nothing. `storage.ts:96-124` (A50) guards an older build, not a second tab of the same build.
- Reach (derived from the code; not run in a browser): with two tabs open, the tab hidden last writes its whole history, so any Enter in tab B followed by B being hidden last loses A's rows; A's definition `X:=5` is lost only when B also defines or purges a name, because the definitions log is saved only on a definition change (`workerEngine.ts:159-165`, `keep`). Android is `launchMode="singleTask"` (`AndroidManifest.xml:22`): one WebView, no reach.

On phase-1, C finds no `X`, no A's row and `Y` defined (B's definitions log and history, read before A's changes, overwrote them). On the branch, C takes the lock and finds `X` and A's row, and no `Y`. A second test: A opens, B opens, "Use here" in B, B defines `Z:=2`, A closes, B is hidden, a new page C reads the store: `Z` is there and nothing A wrote after the hand-over (A defines `W:=3` after it: no `W`).
2. **One writer:** at start the app asks `navigator.locks.request("pascaline-writer", {ifAvailable: true}, …)` and holds the lock for the page's life; the holder writes as today. A tab without the lock writes no key (one check in the store layer, not in each caller), computes normally and shows one status line through i18n: "Pascaline is open in another tab" with "Use here".
3. **Use here:** over a `BroadcastChannel`, the writer flushes, releases the lock and turns read-only (its line says so); the new tab takes the lock and rereads every key before its first write (R106's read guard).
4. **Without `navigator.locks`:** the tab writes as today; the report names where that happens (no heartbeat is built).
