### annabell, A9: key vibration on the owner's phone (F41), branch `p1/annabell-haptics`

**Read:** feedback.md #50 (never tried on a phone with a motor: A4a ran on the Tab One, which has none); `app/src/input/haptics.ts`; `app/src/App.svelte` (`touched()`, `dead()`); `app/src/main.ts` (`loadNative()`); `android/app/src/main/java/io/github/buerlino/pascaline/PascalineHapticsPlugin.java` and `android/app/src/main/java/io/github/buerlino/pascaline/MainActivity.java` (its registration); decisions.md "P7" point 3 (the setting and its defaults); `tools/README.md` (devices).
1. **Tests first:** every change to `haptics.ts` gets a unit test that fails on phase-1 (the existing `recordVibrations` e2e helper covers the web path). The cause comes from the device logs before any change.
2. **Find the cause, with logs, not guesses.** Install a measure build (`./build.sh --dev --measure --install <serial>`), switch Key vibration on, tap keys, and read logcat: the plugin logs `PASCALINE_HAPTICS` for every native pulse (measure builds only), and `adb shell dumpsys vibrator_manager` lists recent vibrations. In this order: (1) no `PASCALINE_HAPTICS` line: the native plugin is never used, so every pulse goes to `navigator.vibrate`, which the Android WebView may ignore: check `Capacitor.isPluginAvailable("PascalineHaptics")` and the dynamic import in `loadNative()`; (2) lines, but nothing felt: the pulse is too short or too weak (15 ms at amplitude 128): try longer pulses and full amplitude; on API 29+ `VibrationEffect.createPredefined(EFFECT_TICK)` or `View.performHapticFeedback(KEYBOARD_TAP)`; (3) lines, and dumpsys shows the vibration ignored or scaled to zero: the system's vibration settings (Android 13+ applies its touch-feedback intensity by usage): set the usage on the `VibrationAttributes`.
3. **Fix** the cause found, in the plugin or in `haptics.ts`. If the defaults (50 %, 15 ms) cannot be felt, propose new ones in the report, measured on the phone.
