### ron, R92: the history is written only after it was read, branch `p1/ron-historyread`
**Lane:** night-safe (no device, no UI change). **Opus** (stored data, P17). **Starts when:** now; first in lane A after tonight's queue (R38a, R38b and R88 touch `state/` tonight: merge phase-1 first). The highest priority of the night review 2026-10-30 (bu-1, S1).
**Why:** (night review 2026-10-30, bu-1, confirmed by its verifier; base `bb90a5e`) A hide or close before the history has been read writes the in-memory empty lists over the stored history.
- `main.ts:70-75` calls `flush()` on `pagehide` and on every `visibilitychange` to hidden; `flush()` (`:56-61`) calls `session.flushHistory()` unconditionally. `session.restoreHistory()` starts only inside two nested `requestAnimationFrame` callbacks (`main.ts:108-119`).
- `flushHistory()` (`state/session.svelte.ts:731-737`) writes `{home, cas}` from memory and checks neither "the history has been read" nor `restoring`; only `saveHistory()` (`:718-722`) checks `restoring`. `kvSet`'s A50 guard (`state/storage.ts:104-113`) compares `DATA_VERSION` stamps only (equal), so the put goes through.
- The verifier's vitest (memory store, Session): launch 1 stores 4 entries; launch 2 calls `flushHistory()` before `restoreHistory()`; printed `before=4 afterHide=0 launch3.home=0`. A flush while the read is in flight printed `during-read flush stored=0 memory=2`.
- Reach: web, a background tab closed unseen (a hidden page fires no animation frame; `pagehide` fires on close); Android, leaving the app within the first frames of a start. Expected: the stored history is untouched (derived: docs/04 6.2 and the comment at `session.svelte.ts:719`).
**Read:** `app/src/main.ts` (`flush`, the two frames); `app/src/state/session.svelte.ts` (`saveHistory`, `flushHistory`, `restoreHistory`, `clearHistory`, `removeItem`); `app/src/state/storage.ts` (`kvGet`, `kvSet`); `app/src/state/session.test.ts` (its memory store); `app/src/apps/shell.svelte.ts` (`flush`, whether an app's store has the same shape); docs/04 6.2.
1. **Tests first (Vitest), failing on phase-1:** (a) a stored history of 4 rows; a new Session calls `flushHistory()` before `restoreHistory()`; the store still holds the 4 rows, and after `restoreHistory()` memory holds them too; (b) `flushHistory()` while `restoreHistory()` awaits its read leaves the store unchanged, and the rows typed meanwhile are saved after the read, behind the stored ones; (c) a read that never settles: no write of `history` at all. A Clear before the read has finished behaves as today (the report says what that is; R98 changes Clear).
2. **The guard:** a `historyRead` flag, set at the end of `restoreHistory()` (after the splice). Until it is set, `flushHistory()` and the save timer only mark the save pending; `restoreHistory()` runs the pending save once the read is in. Guard on "read finished", not on `restoring` alone, so both windows close.
3. **The same check for `shell.flush()`:** if an app's slots are written whole before they were read, give them the same guard and a test; if not, say so in the report with file:line.
4. **Nothing else:** no change to the stamp, the store keys or what a row holds.
**Done when:**
- The tests fail on phase-1 and pass; typecheck, vitest, e2e and the core list pass.
- The report gives the backlog text that removes the Open-bugs line of bu-1 and names any other store written before its read (step 3).
