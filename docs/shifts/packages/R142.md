### ron, R142: a legend that types a variable is italic in every mode, no bold anywhere; Plain keys changes colour only, branch `p1/ron-italicletters`
**Lane:** A, night (before v0.1.0, owner 2026-11-06), Sonnet (CSS, one small spec-derived flag, tests). **Starts when:** R141 is merged (both edit `modes.css` and the legend rules of `Keypad.svelte`).
**Why:** (owner, 2026-11-06, point 11: "no syntax mode should not change the italics and boldness … i actually think italics on the letter helps make them more disdinguishable, considering always being italic? the bold is less of an effect, advise me"; the advice, accepted ("yes i agree on all your inputs"): italic letters always, no bold)
- ISO 80000-2: a variable is italic; function names, units, numbers and constants are upright. The Alpha letters type variable names, and the entry line draws a typed single letter in MathLive's math italic, so the A on the key is the A in the formula. Shift legends are mostly functions (sin⁻¹, eˣ, √, Ans), upright by the same rule.
- Today only Plain keys does it (`app/src/theme/modes.css:2-3`: "bold always means Shift, italic always means Alpha"): bold at `:12-17` (Shift legends, `.shifted .main`, `.sheet .n`, `.bubble`), italic at `:18-21` and `:27-31` with `font-family: "STIX Two Math", …`. That family is not bundled (no `@font-face` for it in `app/src`), and STIX Two Math has no italic face, so where it is installed the browser slants it (a synthesised oblique), and elsewhere a system serif is used. At legend size bold also closes up the small Shift text.
**Read:** `app/src/theme/modes.css`; `app/src/keyboard/Keypad.svelte` (`face`, `hint`, `alphaHint` at `:58-61`, the `.shiftlegend`, `.alphalegend`, `.shifted`, `.alphaed`, `.bubble` rules); `app/src/entry/field.ts:86-88` (MathLive's fonts come from `mathlive/static.css`); MathLive's CSS for the class it uses on a single-letter variable (find it in `mathlive/static.css`; expected KaTeX_Math italic); `spec/keyboard.yaml` (the Alpha layers, the `x` key's x and y, the unit pad `unit_slot` comments `:335-352`); `app/src/units/padCells.ts` and `padView.svelte.ts` (the unit view draws unit cells on the keys); `app/test/flicks.spec.ts`; `app/test/press-feedback.spec.ts`.
1. **Tests first (failing on phase-1):** an e2e over every key and layer, with Plain keys off and on: a legend is italic exactly when its action types one letter (`/^\p{L}$/u`; the Alpha letters A–Z, Greek letters typed by a key layer, x and y on the `x` key), and the italic is a real italic face (its computed `font-family` is the one MathLive uses for a variable, not "STIX Two Math"); `:`, `;`, `#`, digits, operators and function legends are upright; no legend, sheet row number or bubble has `font-weight` above 400 in either mode; in the unit view (the units key on a line with a number) the unit cells drawn on the keys are upright. A vitest that derives the italic flag from the spec (step 2) for every key.
2. **The flag:** the keypad marks a legend span as a variable when its layer's action is `type` of one letter (a helper in `app/src/keyboard/`, used by `hint`, `face` and `alphaHint`; a user key's legend follows the action it holds). The CAS view's lower-case letters are the same letters, italic too.
3. **The CSS:** the italic rule moves out of `modes.css` into `Keypad.svelte` (it is now in every mode, not a Plain keys rule), on the flagged spans, with MathLive's variable font first and a real italic serif after it (`font-style: italic`). The bold rules of `modes.css:12-17` go, and the flick bubble's letter follows the same flag. `modes.css` keeps only colour for Plain keys; its header comment (`:2-4`) says Plain keys turns colour off and changes nothing else, and that the meaning stays in position (Shift top left, the letter bottom left) and in the italic letter.
