## Defaults (Phase 1)

Each entry: the choice, why, the alternatives, and what would change it.

### 2026-10-15 R18f3 (owner): Home draws a non-number from latex()
- **Choice:** a Home result that is not a number is drawn from Giac's `latex()` through `tidyGiacLatex`, as in CAS; numbers keep our formatter. In `tidyGiacLatex` a top-level `==` loses the brackets round its sides (`xy==2`, as `a≠b`), and a digit keeps its `·` before a fraction, since `2\frac{\pi}{7}` reads as the mixed number 2 + π/7 (this changes CAS too).
- **Why:** the text form drew `pi`, `cos` and `/` as letters; the kept `cos(π/7)` identity now draws as textbook maths.
- **Alternatives:** extending `homeResultToLatex` (a second renderer to keep in step).
- **Would change if:** a Home-only form is wanted for some non-number. Known: a string result draws without its quotes (`"hello"` as hello; review 2026-10-16), and in a list an `==` keeps Giac's side brackets.

### 2026-10-15 The cursor stops only at a box (F23, R27b; G2 item 50 to confirm)
- **Choice:**
  1. ◀ ▶ ▲ ▼ and every trackpad step skip the inside of a name, the gap between a function name and its bracket, the places right before a template's marks (piecewise's `if `, ∫'s d, ∂, the evaluate-at subscript) and right after ∫'s d (the template's `\,\mathrm{d}`; any other upright letter is an atom like any other). A typed key takes no style from its neighbour (R27c). ▲ ▼ settle to the left. After `if ` a key types maths.
  2. The parser refuses a bare function name followed by a term and a bracket: `sin 7(2)`, `sin x(x+1)`, `ln 7(2)`, `log₂ 7(8)`, `cos 2π(x)`, `sin 2|x|` give "put its whole argument in the brackets". `sin 2x`, `sin x cos x` and `sin(2)(3)` read as before (owner, 2026-10-15: "I accept your recommendation on item 50").
- **Why:** a 7 between sin and its bracket gave sin(7·2) with no mark, and one inside a name broke it. The cursor rule removes the stops; the parser rule also covers a tap there, pasted LaTeX and a hardware keyboard (principle 3).
- **Alternatives:** make names atomic MathLive macros (changes the LaTeX the parser reads; rejected); settle the cursor after a tap too (the parser rule already covers it).
- **Would change if:** the G2 (item 50) lets the cursor stop between SIN and its bracket and reads what is typed there.

### 2026-10-15 Hardware keys take the keypad's path (F27, R31)
- **Choice:**
  1. A hardware `-` is the − key (sub), so on an empty line after a result it starts with Ans, like `+ * / ^`; the (−) key stays on the keypad.
  2. ASCII characters no key types (`\ [ ] { } ' " $ % & ? @ ~` and the backtick) do nothing. `'` and `"` are not minutes and seconds, `%` is not /100: no keypad key types them. (R31's open point on `'` and `"`, settled as built by the Opus pass of 2026-10-15: dead until the owner reaches for them on a desktop.)
- **Why:** the G2's flow, and the Ans chip is visible on the line; a line typed on a hardware keyboard must parse as the same keys pressed on the keypad.
- **Alternatives:** for 1, (−) on an empty line.
- **Would change if:** for 1, owner use on a desktop; for 2, a key or palette item that types one of these characters.

### 2026-10-15 The cursor goes where the user aims (F33, F34; R42, R43; G2 item 57 to confirm)
- **Choice:**
  1. A finger tap puts the cursor where the finger went down, as a mouse click does. MathLive's second placement on the lift (touch only) is undone.
  2. ▶ that leaves a template and lands at the end of the box that holds it stops there, before it goes on to an empty box: ÷ ÷ 1 ▶ 2 ▶ stands after ½ in the numerator, and the next ▶ goes to the empty denominator. Everywhere else R10's rule stays: while an empty box lies ahead, ▶ jumps to it over the marks between boxes. The end of a box is `endsBox()` (`entry/boxes.ts`), so ▶ also stops before EQ's comma, a DMS mark and ∫'s `\,` d, and leaving a DMS counts at its ″. Brackets a key put round a selected □ (R17) count as a template too. Built in R43 (`6c65ce8`).
- **Why:** both bugs put the next key somewhere the user did not aim, with no way to aim better: the end of a numerator that holds a fraction, a power or a root is skipped by ▶ (x²/(+1) instead of (x²+1)/□) and, on the phone, a tap there lands at the start of the line. The mouse path shows MathLive's first placement is right (11 of 40 tap points differ only for touch; backlog F33).
- **Alternatives:** for 1, clear MathLive's private bounds cache before its second placement (one line, but it breaks on an upgrade). For 2, let ▶ jump only within the template the cursor is in; rejected, since ∫ and ∂ are sequences of atoms and their marks would become stops again.
- **Would change if:** the G2 (item 57) stops ▶ after a power in the middle of a box too, so point 2 widens; the owner finds the strip after an inner fraction too narrow to tap on the R42 APK (about 8 px), so a wider target is added.

### 2026-10-14 ⌫ and Del keep a template whole (F15–F21, R26a–R26h; G2 items 46, 49 and 51 to confirm)
- **Choice:** "⌫ at a bracket" (below) extended to every template the keys build (‸ is the cursor; "box" is a □ of the template). After any ⌫ or Del:
  1. **No half template:** never a half pair (`\left.` with a real `\right)`, or the reverse; the evaluate-at template owns its `\left.`), never an exponent, subscript or limits without its base, never a template that lost a box or a mark (`EQ(,□)`, `\lim_{\to□}`, a matrix cell without its □).
  2. **A box is never deleted:** an emptied box shows □ again, and a selection that is all of a box leaves □ when deleted (R26d). The marks between boxes (the comma of EQ, → of lim, = of Σ and Π, ∂, the `\,` and d of ∫, ° ′ ″, the evaluate-at bar, the `if` of piecewise) and the brackets go only with their whole template. A table's row is never removed: ⌫ at the start of a row steps to the end of the row before it, so a matrix keeps the shape its key gave it (R26g; settled as built by the Opus pass of 2026-10-15; rows become removable only if the owner asks: ⌫ at the start of an empty row's first cell, in a table of more than one row). A body that ⌫ empties character by character (`log 2 ⌫`) shows □, selected, and the next ⌫ removes the template (R23, R26c; settled 2026-10-15).
  3. **⌫ inside a template stays inside it:** at the start of any box but the first, ⌫ steps to the end of the box before it (as ◀) and deletes nothing; Del at the end of any box but the last steps to the next one. An empty exponent on a typed base is the exception: ⌫ at its start removes it alone, the cursor after the base (`5 xʸ ⌫` → `5`; the owner, 2026-10-15). A bracket base still steps, since its pair may be the key's own (the one-line x⁻¹). A stacked fraction is the other exception, from the G2 (item 47): ⌫ at the start of its denominator removes the fraction and joins its parts, the cursor between them (`5/23` → `5‸23`); Del at the end of the numerator is the mirror. A key's argument goes alone the same way: when only the box a #@ key took holds something (a mixed number's whole part, DMS's degrees), ⌫ at the start of any other box removes the template and keeps it. ⌫ right before typed degrees acts on the line (R26h). ⁿ√ at the start of its index selects the root first whenever either box holds something (R26e). ⌫ never jumps out of a box and deletes what stands before the template. lim has no exception: with empty bounds, ⌫ at the start of a typed body steps back through the target and the variable before it removes lim and keeps the body, three presses (R26f; settled as built by the Opus pass of 2026-10-15; an exception like the empty exponent's is added only if it feels slow on the phone).
  4. **⌫ at the start of the first box** removes the template, as "⌫ at a bracket" says: at once when every box is empty; with the content kept when only the main box (`#0` in `spec/keyboard.yaml`) holds something. When another box holds something (a bound, an index, a second cell, a typed exponent), the first ⌫ selects the whole template and a second ⌫ deletes it, so nothing from two boxes is ever joined. This covers a log base, a bound, the evaluate-at bounds (never dropped in one press), an exponent on a pair and EQ's second value (R23; settled as built by the Opus pass of 2026-10-15). Del at the end of the last box is the mirror.
  5. **⌫ right after a template** steps into its last box, as it already does after a root or a fraction, and deletes nothing; it never removes a closing bracket alone (F15), and a filled matrix is no longer deleted whole by one ⌫. Del right before a template is the mirror. Built for pairs and the function names that own no box in R26c (`stepIn()` in `app/src/entry/delete.ts`) for powers, a pair's too, in R26d (`deleteAtPower()`), for fractions, roots, ∂ and the mixed number in R26e (`deleteAtBoxes()`), for lim, Σ, Π and ∫ in R26f (`bigOp()`, through `deleteAtBoxes()`), and for matrices, vectors and piecewise in R26g (`table()`, through `deleteAtBoxes()`; no row is removed), and for the log base, EQ, DMS and evaluate-at in R26h (`logBase()`, `equation()`, `dmsAt()`, `evalAt()`, through `deleteAtBoxes()`).
  6. **An exponent stays on its base:** ⌫ never moves an exponent onto another base (`5eˣ` with the e deleted is not `5^…`); when ⌫ empties a base that carries an exponent, the base shows □. Built in R26d (`deleteAtPower()` in `app/src/entry/delete.ts`): eˣ's e and 10ˣ's 10 are the key's own marks and go with their exponent; an exponent 2 or −1 on a □ base counts as the key's own.
  7. **Every way in takes this path:** the ⌫ key, Shift + ⌫ (Del), their auto-repeat, and the hardware Backspace and Delete keys (F16).

### 2026-10-14 Nothing takes focus while the app is away (F11–F14, R25a–R25c)

  3. ### 2026-10-14 ⌫ at a bracket (F10, R23; G2 item 44 to confirm)
- **Choice:** ⌫ with the cursor right after an opening bracket removes the whole template the bracket belongs to and keeps what was inside, with the cursor where the opening bracket was. A function's brackets go with its name: `log(‸2+3)` → `‸2+3` (‸ is the cursor); `log(log(□))` ⌫ → `log(□)` ⌫ → empty line, one ⌫ per log key. A plain pair `( )`, `| |` or `{ }` loses both brackets: `5(‸2)` → `5‸2`. An empty pair goes the same way. Shift + ⌫ (Del) right before a closing bracket is the mirror case. The rule never leaves half a pair (`\left.…\right)`) on the line. Built in R23 (`app/src/entry/delete.ts`, loaded with MathLive). When another box of the template holds something (a log base, bounds, an exponent on the pair, EQ's second value), the first ⌫ selects the whole template, as in "keep a template whole" point 4; the evaluate-at bounds go with their template only when empty.
- **Why:** it is the rule ⌫ already follows at the start of a root, a fraction's part or a box on our line (one rule for every template), and each key press is undone by one ⌫. The name must go with the brackets: the parser reads `\log2+3` as `log10(2)+3` (`tools/probes/parse.ts`, 2026-10-14), so keeping it would change the meaning of `log(2+3)` without a mark.
- **Alternatives:** keep MathLive's invisible bracket and make the second ⌫ step out (it still leaves a syntax error on the line); drop only the brackets and keep the name (the meaning trap above); delete the name before the pair and keep the brackets (`(2+3)`).
- **Would change if:** the owner's G2 does something else for `SIN(23)` and `5(2)` with ⌫ right after `(` (G2 item 44). Then the G2 way wins, unless it leaves a half pair. Extended to every template by "⌫ and Del keep a template whole" (above).

### 2026-10-11 Mixed numbers in textbook entry (R10, 2026-10-13)
- **Choice:** the mixed number is a Tmpl template: a whole number, then `\tfrac{□}{□}`, which the parser reads as `(2+1/2)`. `\tfrac` after anything but a whole number is an error, never a product (`x\tfrac12` would silently be x/2). A digit directly before a plain stacked fraction still parses as `2*1/2`. While typing, a b/c inserts the plain stacked fraction, as ÷ does.
- **Why:** P1 only accepts what our keyboard produces; a separate template keeps the parser unambiguous. The owner's G2 answered item 29: a b/c toggles the last result decimal ↔ fraction, with no mixed step, so L2's "a/b twice" is gone.

### 2026-10-11 Entry and history behaviour (updated 2026-10-12)
- **Cancel:** while a job runs, it stops the job and keeps the history (the entry is marked cancelled). When idle, it closes a list or clears the entry line. Enter while a job runs is ignored.
- **Esc** clears the entry line or closes a list; **Shift + Esc (Clear)** wipes the current view's history (the reference's keys, P4).
- **History:** Home and CAS keep separate histories over one shared variable context. Tapping a result inserts it (see "Results are insertable"). History, settings and the current view are stored in IndexedDB.
- **Shift and alpha** are one-shot; alpha gives capitals and shift + alpha lower case (P4). Alpha twice locks it (see "Alpha lock").
- **One-line mode** shows fractions, roots and exponents linearly (see "One-line entry mode").
- **Sto▶** is Shift + ᴇ (P4; the exponent key, id `emark`, at r7c1 in `spec/keyboard.yaml`).
- **Why:** each is the fastest path for keyboard use (principle 2) and matches what a calculator user expects. Cancel is ours (P4 item 6); the rest follows the reference's keys.

### 2026-10-11 Bit-reproducible release engine
- **Finding:** clang 19 at `-Oz` gave different object files from run to run under address-space randomisation (ASLR), so two container builds produced different `giac.wasm` files. Their output was still identical: 0 differences in 476 golden outputs.
- **Choice:** `engine/giac/build-wasm-release.sh` runs the engine build under `setarch -R` (ASLR off) inside the container. That needs `--security-opt seccomp=unconfined` for rootless podman, so the container can call `personality()`. It still only mounts scratch copies. Two builds in one checkout and one from a fresh clone all give `giac.wasm` SHA-256 `ab5ca4eb…3003a`.
- **Why:** F-Droid's reproducible builds need the same bytes on every build (principle 1).
- **Would change if:** a clang or Emscripten update makes `-Oz` deterministic, or F-Droid's build server can't turn off ASLR (then we look for the compiler pass that depends on addresses).

### 2026-10-11 Residual check thresholds for Solve and Plot analysis
- **Choice:** a root is accepted silently when its relative residual, evaluated at 30 digits, is ≤ 1e-15. 1-D roots above that are shown with ⚠. For systems, a residual < 1e-6 is shown with ⚠, and anything worse is reported as no solution (Giac's `hybrids` returns the guess unchanged when it fails, so the check is the only guard).
- **Why:** docs/02 section 4 requires substituting every root back. 1e-15 is far above 30-digit noise and far below anything a 12-digit display would show as wrong.
- **Alternatives:** an absolute threshold (fails for large-scale equations), or showing every residual (clutter).
- **Would change if:** golden or user cases show false ⚠ on well-conditioned roots, or the user reverses P5(d) (the reference shows no ⚠; items 12–14, 20).

### 2026-10-12 Powers after a compound term (L8)
- **Choice:** x², xʸ and x⁻¹ (the keys whose template starts with `#@^`) wrap the term before the cursor in brackets when it is a fraction, a root, a power or a mixed number: `1 a/b 2 ▶ x²` → `\left(\frac12\right)^2`, `2 xʸ 3 ▶ x²` → `(2³)²`. After a number, a name, a bracket or a function call the plain `^` stays (`1+3 x²` → `1+3²`, `sin(2) x²` → `sin(2)²`). With the cursor still inside a numerator or denominator the key raises the last term there (`1 ÷ x x²` → `1/x²`); ▶ leaves the part first. Inside a mixed number it raises the whole number.
- **Why:** user, 2026-10-12 (whole fraction after ▶; inside part while inside, so `1/x²` stays easy to type). A bare `^` after a fraction or root gave an empty base or read ambiguously, and after a power MathLive merged the new exponent into the old one (`2^{32}`).
- **Would change if:** the Virtual Calculator shows another behaviour for Textbook `1 ÷ 2` then x² (not a G2 item yet).

### 2026-10-11 Solve and analysis time limit
- **Choice:** a 30 s hard Giac timeout per solve or analysis call. Cancel is the user's own limit.

### 2026-10-11 Signed area in Plot analysis
- **Choice:** Romberg at 30 digits, then the exact `int` (0.5 s budget), then `gaussquad` with ⚠, always cross-checked against `gaussquad`. A pole inside the interval gives "no area" (G2 item 22).
- **Why:** Romberg is fast on smooth functions but doesn't converge at kinks; the exact integral covers those.

- **Would change if:** the G2 shows the reference searching beyond the window.

### 2026-10-11 Function app defaults (G2 items 19, 23–25; updated 2026-10-12)
- **Choice:** default Plot window x ∈ [-10, 10], y at the same scale as x, centred on 0 (ours; the reference uses -15.9..15.9 by -10.9..10.9, item 23); canvas renderer with "hybrid" sampling (D7, fastest on desktop: 59.3 fps at CPU ×4). Trace step = a 1-2-5 step near window width / 200: **0.1 at the default window, as on the reference** (item 24). ### 2026-10-11 Solve app variables and results (G2 items 12–14, 20 answered; differences kept, P5(d))
- **Choice:** the Solve app keeps names as typed (`x` and `X` are different unknowns; the Function app maps `X` to `x`). New unknowns start at 0. With one equation, Solve finds the selected unknown and holds the others fixed; with N equations it finds N unknowns, the selected one first. A failed solve or a failed residual check shows ⚠ with the engine's info line. A polynomial with exactly one real root also writes that root into the value.
- **Why:** engineers expect case-sensitive names, as in the CAS. Starting at 0 is predictable.
- **Alternatives:** fold case (would clash with CAS variables), or start from the last value used anywhere.
- **Would change if:** the user reverses P5(d) (the reference returns the guess with "Extremum found" or a huge value with "Zero"; we keep "no root found" with ⚠). Subscripted names (`x_1`) are solvable (L1, `a3ddd52`): Giac reads `x_1` as a plain variable (checked 2026-10-11: `type(x_1)` → identifier); only `<number>_<unit>` is a unit.


### 2026-10-11 Minimum WebView: modern Chrome WebView, with an "update" notice below it
- **Choice:** minSdk stays 24 (Android 7). Below that, we also require a minimum WebView version, the highest floor among our Vite build target, the Emscripten build (Giac) and MathLive : **Chrome 95** (Giac is built with `-fwasm-exceptions`; Vite es2022 needs about 94, module workers 80). MathLive 0.111.1 uses `:has()` and `@container` (Chrome 105), which most likely only affects styling (not verified). An inline ES5 check in `app/index.html` feature-detects what we need. On an older WebView it shows one line asking the user to update Android System WebView / Chrome, instead of a blank page.
- **Why:** the Galaxy S8+ (Android 9) still has its factory WebView, Chrome 72 (2019). Our bundle stops at the first `?.`, and the wasm builds need newer features anyway. On Android 7–9 the WebView is Chrome and updates from the app store (Chrome 138 is the last for Android 8/9), so real users on these devices run a modern WebView. Transpiling down to Chrome 72 would cost bundle size and start-up time on every device (principle 2), and the wasm feature gap would remain.
- **Alternatives:** a legacy build (`@vitejs/plugin-legacy`, wasm built without exceptions or bulk memory): two builds to test, slower everywhere. Raising minSdk instead: wouldn't help, because the WebView version is what matters.
- **Would change if:** testers report Android 7–9 devices that can't update their WebView (e.g. no app store) in meaningful numbers.

### 2026-10-11 Parser: odd roots, lists, decimal comma, one-letter functions (L6)
- **Choice:** a root with an odd whole-number index is the real root (∛(-8) = -2 in Home and in plots; the CAS view leaves `-8^(1/3)` unsimplified, as Giac does with `8^(1/3)`). The reference gives -2 for `(-8)^(1/3)` typed as a power (G2 items 4 and 11, Virtual Calculator; its root key wasn't tried); our power form stays complex (P5(b)), so only the root template matches it, and the option `realOddRoots: false` restores the principal complex root. `{…}` is a list. A `decimalComma` input option reads `3,5` as 3.5 and then separates arguments with `;`. After `p(x):=…`, `p` is a function for the rest of the session (f, g and h always are).
- **Why:** engineers expect ∛(-8) = -2. Lists and user functions are things our keyboard can produce, and the decimal comma is common in Europe.
- **Left open:** `x^y^z` (our keyboard can't produce it) and units (a separate feature); the reasons are in `parser.yaml`.
- **Would change if:** the G2 shows how the decimal-comma setting separates arguments.
