# Probes: check a claim against the code, the engine and the data

Small read-only scripts that answer "what does it actually do today?" without the app or a device. They were
written for the architecture pass ([docs/04-architecture.md](../../docs/04-architecture.md), Appendix A) and the
packages since; one written for a finished package is deleted (rules section 10). They are tools, not tests: a finding becomes a golden case or a unit test
before anything is fixed (CLAUDE.md). Output goes to `tools/probes/_out/` (gitignored); nothing here is shipped,
but six gate stages run probe code (`sweep`, `seqsweep`, `casback`, `viewsweep`, `findcensus`, golden's flags via
`giac-check.mjs`), so a probe edit can change a gate. `npm run typecheck` (from `app/`) also runs `scripts/probe-imports.ts` (G144): every relative import of a probe must name a file that exists and a value its module exports; known failures are listed in that file.
Background on the pipelines they probe: [docs/research/r6-pipelines.md](../../docs/research/r6-pipelines.md).

Run from the repo root. The engine probes need a built engine (`engine/giac/build-wasm.sh`, or `GIAC_OUT`/`GIAC_MJS`)
and `app/node_modules` (`cd app && npm ci`); Node 22 runs the `.ts` files directly.

**Oracle values** (never from memory): `tests/golden/.venv/bin/python -I -c "import mpmath as m; m.mp.dps=40; print(m.ncdf(-6))"`
(set the venv up once as in CLAUDE.md).

**Limits** (owner, 2026-10-20; rules section 10 since 2026-11-05): a script that a finding in a note or report cites lives here, with a row above, in the same commit as the note; a one-line `engine.ts` or `parse.ts` call written in the note counts as the script. Once its package is finished, the probe is deleted (`git rm`; git keeps it) unless a gate, a script or an open package uses it, and the note names it as path and last commit in a code span. Output goes to `_out/`, which is not kept: a finding whose script is not in the repo or in git is (to verify).

**Rules:** read-only against the repo (they write only to `_out/`); no network; downloaded tarballs are read
after their SHA-256 is checked; heavy work (a build, a timing series) takes the host-cpu lock (`tools/devlock.sh`).
